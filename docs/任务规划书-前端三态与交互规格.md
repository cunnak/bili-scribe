## 0. 执行者第一页（硬约束）

1. **前端是原生 JS**：无框架、无构建链、`file://` 加载。沿用 `ui.h()` / `WB.rpc()` / `WB.mediaUrl()`，不引入任何新依赖，不引入打包器。
2. **CSP 不许放宽。** `index.html` 的 `connect-src 'none'` 是产品契约（页面不做任何网络动作，全部在 Python 侧）。"加个本地 HTTP 服务方便前端拉状态"这类方案一律否掉。
3. **业务文本一律 `textContent` / `ui.h({text})`**。项目标题、UP 名、错误原文都来自外部，禁止 `innerHTML` 拼接。`ui.h({html})` 只给固定图标与固定文案。
4. **颜色只准来自 `css/tokens.css`**（`scripts/check_colors.py` 会扫）。新增状态色先加 token，不在页面里写 hex。
5. **界面文案里"关掉 X 会更快/更省"这类收益承诺，没实测数据不许写**（仓库既有纪律）。本次新增文案只写机制，不写收益。
6. **引用代码位置用符号名，不给行号**（行号会漂）。本文定位点均可 grep：`paintList()`、`state.loading`、`openJobsModal()`、`unwatchJob()`、`ui.errorFrom`。
7. Python 一律 `.venv/Scripts/python.exe`；中文探针先 `export PYTHONIOENCODING=utf-8`；全量回归 `.venv/Scripts/python.exe -m pytest tests/wb -q`。
8. 新建 `tests/wb/*.py` 落地后立刻 `git add`（只 add 不 commit）。改大文件只用字面替换，禁止 `read` 全文 + `write` 整写。

## 5. 交互规格（开发可直接照做）

### 5.1 统一状态原语（P0 卡的基座）

在 `ui.js` 新增三个函数，**不新增 CSS 类**（复用 `.empty` / `.callout`）：

```js
// 1) 加载态：图标 + 一句机制文案，不写"请稍候"这类空话
ui.loading = function (text) {
  return h("div", { class: "empty", role: "status", "aria-live": "polite" }, [
    h("div", { html: ui.svg("spinner") }),
    h("div", { class: "empty__hint", text: text || "读取中…" })
  ]);
};

// 2) 错误态：必须带出口。onRetry 为空时才允许没有按钮，且文案要写清下一步
//    opts = { title, message, retryText, onRetry }
ui.errorBlock = function (opts) {
  var o = opts || {};
  var kids = [h("div", { class: "empty__title", text: o.title || "读取失败" })];
  if (o.message) kids.push(h("div", { class: "empty__hint", text: o.message }));
  if (o.onRetry) {
    kids.push(h("button", { class: "btn", type: "button",
      text: o.retryText || "重试", onclick: o.onRetry }));
  }
  return h("div", { class: "empty", role: "alert" }, kids);
};

// 3) 从 RpcError 直接产出错误块，吃掉 retryable
ui.errorFrom = function (err, onRetry, title) {
  return ui.errorBlock({
    title: title || "读取失败",
    message: (err && err.message) || "未知原因",
    onRetry: (err && err.retryable) ? onRetry : null
  });
};
```

**硬规则**：

1. 页面里凡是 `catch` 后只画文字、不画出口的，一律改成 `ui.errorFrom(err, retryFn)`。
2. `onRetry` 只在 `err.retryable === true` 时给；不可重试的错误（`VALIDATION` / `NOT_FOUND` / `LLM_NOT_CONFIGURED`）**不给按钮**，改在 `message` 里写清下一步——`subtitles.js` 的 `optErrorText()` 已有这个写法（"去 设置 → 模型 填好接口地址与 Key"），照抄。
3. `ui.loading()` 只用于**首次**加载；已有内容时的刷新用"行内禁用 + 按钮文案变更"（`summary.js` 的 `progressBlock()`、`clips.js` 的 `renderActions()` 已是这个范式）。

### 5.4 空态 vs 错误态的判据（P1-3）

| 情况 | 归类 | 渲染 |
| --- | --- | --- |
| 请求成功、返回 0 条 | **空态** | `ui.empty`，灰调，给下一步 |
| 请求成功、字段缺失（如 `has_transcript === false`） | **空态** | `ui.empty`，给下一步按钮 |
| 请求失败（`RpcError`） | **错误态** | `ui.errorFrom`，给重试或下一步 |
| 校验失败（`VALIDATION`） | **错误态**（不可重试） | `ui.errorBlock` 无按钮，文案写"改哪儿" |

据此改造两处：`subtitles.js` 的 `state.error = "还没有字幕…"` → 新增 `state.empty`；`summary.js` 的 `start()` 里 `has_transcript === false` 分支 → 空态。

### 5.5 路由生命周期契约（P1-6 / P1-7）

**规则**：只要页面里出现以下任一，`router.define()` 就必须带 `destroy`——

- `setInterval` / 长周期 `setTimeout` 轮询
- `window.addEventListener("resize" …)`
- `WB.on(...)` / `WB.events.on(...)` 订阅
- 自建 `IntersectionObserver`

现状盘点：

| 页面 | 有无 destroy | 需补 |
| --- | --- | --- |
| `library` | 有（断开 `sentinelObserver`） | — |
| `subtitles` | 有（`pageToken++` / 清 saveTimer / 补存草稿 / `disposeMedia`） | — |
| `clipper` | **无** | 清 `setInterval`、移除 `resizeHandler`、`player.destroy()`、`timeline.destroy()` |
| `merge` | **无** | `unwatchJob()`、清 `timer` |
| `summary` / `publish` | **无** | `publish` 有 `state.loaded` 缓存，需提供 `unmount()`（当前无订阅，可先做空实现 + 清缓存标记） |

**机械闸**（随卡落地）：`tests/wb/test_web_router_lifecycle.py` —— 扫 `web/js/pages/*.js`，凡出现 `setInterval` / `window.addEventListener("resize"` / `WB.on(` 的文件，必须同时出现 `destroy:`。扫描域走既有 `WB_WEB_ROOT` 开关。牙齿：删掉 `merge` 的 `destroy` → 必须红。

### 5.6 状态条契约（P0-1 / P1-8）

拆成四个独立槽，各有独立数据源与独立失败文案：

| 槽 | 数据源 | 加载 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| 任务 | `job.*` 事件 + `job.list` 对账 | "—" | "下载 N · 转录 N · 导出 N" | 保持上次值，`title` 写"上次同步 HH:MM" |
| 磁盘 | **新增** `app_info()` 的 `disk: {media_root, free_bytes, total_bytes}` | "磁盘 …" | "磁盘 128.4 GB" | "磁盘 ?" + `title` 挂原因 |
| 依赖 | `info.deps` | "检查依赖…" | "依赖齐全" / "缺少 ffmpeg" | "依赖未知" |
| 版本 | `info.version` | "v—" | "v0.9.4" | "v?" |

**注意**：新增 `disk` 属于后端改动，`app_info()` 是 `--check` / `info` 共用的载荷，**只增不改**（仓库"载荷只增字段"惯例）。`shutil.disk_usage()` 对不存在的路径会抛 `OSError`，必须 try/except 后返回 `None`，界面按失败态画。

### 5.7 焦点与可达性（P2-4 / P2-5）

`ui.modal()` 补三件事：

1. 打开时把焦点移到 `panel`（`tabindex="-1"`）或首个可聚焦控件。
2. `Tab` / `Shift+Tab` 在 `panel` 内循环（`onKey` 里拦 `Tab`）。
3. `close()` 时把焦点还给打开前的 `document.activeElement`。

`clips.js` 候选卡片补 `onkeydown`：`Enter` / `Space` → `select(id)`，与 `library.js` 的行同一写法。

### 5.8 文案规范（P2-3 / P2-6 / P2-7）

1. **toast 等级只准三个值**：`info` / `success` / `error`，加 `warning`。归一放在 `ui.toast()` 内部（`level === "warn" ? "warning" : level`），治本，不用改 30 个调用点。
2. **错误文案三段式**：做什么失败了 + 为什么（后端原文）+ 现在能做什么。中间那段必须来自 `err.message`，不许自造。
3. **双通道禁止**：`silent: true` 的调用由页面自己画错误块；非 `silent` 由 `rpc.js` toast，页面**不再**重复画同一句。二选一。
