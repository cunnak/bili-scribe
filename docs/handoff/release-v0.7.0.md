## 这个版本解决什么问题

**多了一套浅色皮肤，而且换肤是真的换肤。**

原来只有一套深色配色，荧光黄绿配炭黑，看久了眼睛累；换个环境（白天、投影、旁边有人看）也不合适。这一版加了第二套浅色皮肤「异客巡展」，顶栏点一下就换，立刻生效，下次启动还是这一套。

但真正花时间的不是调色，是**把颜色收干净**。原来的 `index.html` 里，`--acid` 这类变量只覆盖了一部分，剩下大量颜色是写死的：`rgba(216,242,75,.45)` 出现 7 次、`#C8CFCB` 出现 6 次、`#0A0B08` 出现 5 次……`<style>` 里一共 79 处字面量、40 种不同写法。这些不搬进变量，换肤就只能换一半——按钮换了、提示条还是橙的，卡片换了、分隔线还是白的。所以这一版先按**用途**（不是按数值）把这 79 处收进变量，颜色变量从 13 个增到 26 个，再谈第二套皮肤。

## 两套皮肤

| key | 名称 | 底色 | 配色来源 |
|---|---|---|---|
| `ark` | 终末地 | `#0D0F10` 深色 | 默认，原样保留 |
| `exhibition` | 异客巡展 | `#FAFAF7` 浅色 | 明日方舟线下展（INTERACTIVE EXHIBITION）海报 |

浅色那套不是"把深色反过来"。参考的海报是近纯白底 + 大量留白 + 细黑描边的小图标，颜色只用在色块、圆点、标签这种小面积上。照着这个逻辑重新配了一遍，几个不能照搬的地方：

- **荧光黄绿当文字在浅底上只有 1.54:1**，完全读不清。所以文字另配一支深橄榄 `--acid-tx`（`#4A6B12`，5.90:1），而 `--acid` 那支亮黄绿只用来做色块、进度条、按钮底——它上面压深字（12.2:1）没问题。
- **橙色同理**。`#FF6B35` 在浅底 2.71:1，不合格，换成洋红 `#C4186F`（5.42:1）——正好也是海报三色之一。
- **`--paper #E8E2D4` 在浅底 1.24:1**，等于消失，换成 `#2A3134`（12.65:1）。
- **叠层方向要反过来**。深色皮肤里 `rgba(255,255,255,.035)` 是"提亮一点点"，白底上照搬就完全看不见了。所以引入 `--ink-rgb`，深色是 `255,255,255`、浅色是 `0,0,0`，7 处 hover、2 处网格、各处描边全部改成 `rgba(var(--ink-rgb),...)`，换肤时整组自动反转。

深色皮肤**逐像素没变**。这一点是机械验证的，不是靠肉眼：把改动前后的 `index.html` 剥掉两套变量块和新增规则、展开所有 `var()`、规范化空白之后逐字比对，结果完全相同（归一化长度都是 25722 字符）。这条是硬要求——加皮肤不该让老用户发现界面有任何变化。

## 桌面版连标题栏一起换

窗口标题栏和启动底色不在网页里，是 `desktop.py` 用 `DwmSetWindowAttribute` 单独设的。不跟着换会有两个难看的地方：

- **启动闪一下**。窗口出现到页面画完之间有一段空白，底色对不上界面 `--bg` 就会闪出另一种颜色。
- **浅色皮肤挂一条深色标题栏**。所以标题栏改成按底色亮度（`0.299r + 0.587g + 0.114b < 128`）自动选深色还是浅色文字。

换肤时 `set_skin` 会顺带重刷一次标题栏，不用重启。

## 打 exe 时抓到一个会让桌面版直接打不开的 bug

这个值得单独说，因为它是**打包之后才暴露、而当时的探针判据判不出来**的。

桌面版把当前皮肤告诉页面的方式原来是拼查询串：`index.html?skin=exhibition`。网页版这么写没问题，但桌面版加载的是 `file://` URI——**查询串会被 WebView2 当成文件名的一部分**，于是它去找一个叫 `index.html?skin=exhibition` 的文件，找不到，窗口里显示的是浏览器的「未找到文件 / ERR_FILE_NOT_FOUND」页。

更麻烦的是探针当时判它"通过"了。原来的判据是"窗口画出了东西"+"截图颜色数够多"，而那张报错页白底、蓝紫大叉、彩色浏览器徽标，颜色数上万——两条判据全都满足，探针还打印了「exe 能启动、能开窗、能渲染」，退出码 0。是看截图才发现窗口里根本不是我们的界面。

改了两处：

- **改用 hash**：`file://...#skin=exhibition` 是合法的，片段不参与文件解析。网页版仍然支持 `?skin=`，两条都认。
- **探针换判据**：不再数颜色，改成查**我们自己的品牌色**——顶栏那块 `--acid` 荧光黄绿斜块，报错页里不可能有。这里还踩了一次：第一版按 RGB 逐通道比对写死的 `#D8F24B`，真截图里那块是 `(214,253,2)`（DWM 合成叠了色彩管理，蓝通道被改写），硬比会假红；改成按色相判（G 最亮、R 也高、B 被压低）才稳。

现在探针跑出来是「品牌色占 0.65%」；对报错页是 0。

## 皮肤名写错会当场报错

`ui.skin` 填了个不存在值（比如 `exibition`）时，**配置加载直接失败并列出可选值**，不默默退回默认。

理由是这个坏法特别隐蔽：CSS 里没有对应变量块时，所有 `var()` 取不到值，界面变成一片白板——而配置文件本身看上去完全正常，日志也没有异常，只有界面上什么都没有。宁可启动失败让人当场看见。

## 切换只写一个字段

跟「总结角色」同一条路子：`POST /api/skin` 只改 `config.yaml` 的 `ui.skin`，**不走保存整份设置**那条路——那条要求把明文 `api_key` 再交一遍。写盘失败时内存里的值会回滚，否则界面显示新皮肤、重启又变回旧的。

## 打发布包时也抓到一个 bug

`scripts/package.py` 原来是遍历整个目录打 zip。这个仓库的工作区里长期堆着调试脚本、抓下来的截图、跑测试留下的 json/txt，于是 0.7.0 第一次打出来是 **386 个文件 / 57 MB**，而上一版是 86 个文件 / 1.2 MB。多出来的全是 `report/shots/*.png` 和 `poll_task.py`、`sub_body.txt` 这类中间产物。

改成**以 `git ls-files` 为准**：发布包的内容边界就是仓库跟踪的文件，未跟踪的属于工作区噪声。现在 87 个文件 / 688 KB。不在 git 仓库里跑时直接报错，不悄悄退化成遍历目录——那正是打出脏包的那条路径。

## 实测验证

- **深色皮肤逐像素不变**：剥变量块 + 展开 `var()` + 规范化后逐字比对，`IDENTICAL`。
- **浅色皮肤对比度全项达标**（浅底 `#FAFAF7` / 卡片 `#FFFFFF`）：正文 17.09、次要正文 9.51、muted 5.51、dim 3.55、文字用黄绿 5.90、洋红 5.42、`--on-acid` 压亮黄绿 12.23。
- **真机截图逐区核对**：用真服务 + headless Chrome 各截 1440×900 全页，两套皮肤各一份，逐区看了顶栏斜块与斜纹、刻度尺 64 根、进度条分段、卡片斜切角与 `01/02` 编号、提示条、右栏版本面板与 token 统计、底栏、皮肤浮层、设置抽屉（输入框、下拉、复选框、保存按钮）。抽屉和浮层是默认关着的，另外写了两个探针页把它们打开再截。
- **`--ink-rgb` 反转生效**：浅底上刻度尺、网格、hover 全部可见，没有消失。
- **打包后的 exe 真跑过**：`dist/bili-scribe.exe`（28.2 MB）在系统临时目录里启动，窗口标题 `bili-scribe 0.7.0`，截图里品牌色占 0.65%，exe 旁边没有多出文件。浅色皮肤下也跑过一遍：品牌色同样 0.63%，窗口底色与界面 `--bg` 一致，没有闪。

测试：40 离线 + 49 HTTP + 210 前端，全部通过。前端从 171 加到 210，新增的 39 条全是行为断言——包括「切回默认皮肤时 `data-skin` 必须是 `null` 而不是 `"ark"`」（写成 `"ark"` 会让两套配色同时命中，谁赢取决于优先级）、「回写失败时皮肤照切但提示要报错」、以及两套皮肤 21 个颜色变量逐项齐备且除三个间接引用外无同值。

写这些测试时抓到三个真缺陷：

1. `pickSkin()` 里赋值和渲染顺序写反了——界面换了、chip 还显示旧名字。
2. 前端测试的假后端缺 `set_skin`——真后端有、假后端没有，这种漏法在源码版永远暴露不出来。
3. **`/api/skin` 这条真实路由此前一次都没被走过**：源码版和前端测试都只验了界面按约定调了接口，没人验接口真的写进了文件。补上之后，三条 HTTP 断言分别钉住了写盘、未知皮肤 400 并列出可选项、以及保存整份设置不会把刚选的皮肤带回旧值。
