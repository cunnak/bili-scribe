## 这个版本新增了什么

**第 8 个角色：「超强思考模式总结」**（`shensi`）。

它的正文骨架是**你指定的**，只有四节，标题不许改：

```
## 作者提出的问题
## 内容的实质
## 他给出的解法
## 他发现了什么
```

## 每一节该怎么写（方法来源）

**「作者提出的问题」用斯金纳式的方法还原。** 他的支点只有一句：要理解一个文本，先恢复它是针对什么问题写下的答案。为什么这一问排第一？因为**它是四问里唯一作者不会明说的一问**——答案是作者会说的（它甚至写在标题里），问题是作者假定你已经知道的。所以入口不是读目录，是**先找他在跟谁较劲**：他在反驳谁？他在纠正哪个流行说法？什么事让他非说不可？**问题从他的敌意里露出来。**

另外三节各有判据：

| 节 | 判据 |
|---|---|
| 内容的实质 | **它是承重墙**——这句话如果被证伪，整条视频就塌了。题目是包装，实质是承重墙 |
| 他给出的解法 | **要分对象**：给个人的／给制度的／给同行的完全是三回事。只诊断没解法时，就写"它停在诊断上"，不要凑 |
| 他发现了什么 | **分清新事实与新解释**：绝大多数视频没有新事实，只有新连接或新解释。混着说是不诚实的 |

**文体纪律是奥威尔式的，而且具体到形态**（不是"要真诚"这种话）：禁过渡句（"接下来我们看看""综上所述"）、禁评价句（"深刻地揭示了""令人深思"）、禁对称壳子、禁排比撑气势、禁用抽象名词顶替具体事实；正面要求两条——**能删掉一个词就删掉**，以及**好文章像一块玻璃窗**（读者该看见东西，不该看见玻璃）。

还有一个判断值得一提：**套话不是用词问题，是位置问题**——它长在段落之间，不长在段落里面。所以规则是"写完先删一遍过渡句和评价句，剩下的才是内容"。

## 遇到没有明确论点的视频

直播闲聊、切片、纯状态记录，硬套四问会产出"替作者编问题"的假货。所以：可以替作者归纳一个他没说出口的问题，但必须做到两件事——**写明这是归纳出来的**，以及**指出素材里哪一处支撑它**。指不出就退回「素材未覆盖」。这一条由批判轮专门盯：**替作者说出他没说的话，是这一行最容易产出的漂亮错话。**

## 批判轮被刻意限定

它只盯两件事：**文体的套话**，和**有没有替作者立论**。并且明确要求它"不要按你自己的清单去挑内容毛病"——因为不加这句，它会顺手把使用者指定的四节结构也改掉（这个坑上一版刚修过一次）。但它必须点名检查**要点与引用**，原因见下。

## 活体验证：第一次就抓到一个缺陷

同一场 30 分钟视频，真模型跑了两遍。

**第一版**：四节骨架都在、套话形态 0 命中、正文质量不错——但 `key_points` 是**截断的原话碎片**：

```
"另类的成人性... loser长成成人是winner的... 尊严的自由地"
"Is not my history, My history begins at this present"
```

根因是**我自己造的**：为了让批判轮不要改掉四节结构，我把它限定在"只盯文体与立论"——于是"要点和引用"这一块**没有任何关口**。

**修完重跑**，要点变成了提炼过的判断：

> 二次元是INCEL群体在现实挫败后主动退缩的精神堡垒
> 政治站队本质是为获取想象性交配权的色情化替代
> 不消费就得掏钱：物质投入是维持虚拟认同的必要代价

而且「发现」一节自己写了：*"这不是一个已经完成的'发现'，而是一个基于社会矛盾的推测"*——正是这一节要的**新事实与新解释之分**。

**两处残留偏差没有修**（如实记录）：

1. `comment_short` 写了 317 字，超出它自己 180–280 的规格（第一遍是 229 字，正常）。
2. 引语里留着一处语音识别乱码数字（"十456岁"），规则要求"要么改对、要么在 `caution` 里说明"，它两样都没做；同一次里 `铝体→女体` 它是改对了的。

没继续改提示词，因为**提示词的改动无法用离线手段验证**，而验证一次要真跑一遍真模型。宁可不改，也不要再叠一条没验过的规则。

## 其它改动

- **新增 `scripts/verify-package.py`**：独立复核发布包。`package.py` 结尾会自检一次，但那是打包者自己的判据；这个脚本换一套判据再验一遍（敏感文件名、凭据、**本机路径**、**真实视频号**、包内版本与工作区是否一致、必备文件是否齐），任何一项不过就退出码非 0，可以直接当发版闸门用。
  它上线第一天就抓出一个真问题：**"本机路径"那条正则要求双反斜杠，而真实的 Windows 路径只有一个**——于是它永远匹配不上，检查显示"0 处 ✓"其实什么也没查。修好之后用"故意造一个脏包喂给它"验证了正反两面：含真实路径的包退出码 1，干净包 0。**一个不会失败的检查，等于没有检查。**
- `.gitignore` 挡掉 `.local/`：在仓库目录里运行 `gh` 时，它会把自己的状态（device-id 之类）写进来，不是项目内容但会一直挂在 `git status` 里。

## 测试

```
python tests/smoke_test.py     # 33 项离线 + 35 项 HTTP

```

全部通过。新增的离线用例钉住这个角色的规格：四问骨架、具体禁令、「归纳必须给出素材依据」、「批判轮专盯文体与立论」、以及要点与引用那两条——**这几条被"顺手优化掉"不会报任何错，只会静默地变成另一个东西**，所以必须有断言看着。

## 安装

下载下方的 `bili-scribe-0.4.1.zip`，解压后按 `README.md` 操作。包内**不含**任何凭据、数据库或本机配置——打包脚本自检一次，`scripts/verify-package.py` 再用另一套判据复核一次（本次结果：敏感文件名 0 命中；凭据、本机路径 0 命中；包内唯一出现的视频号是文档占位符 `BV1xx411c7mD`；包内版本与工作区一致）。

需要 Python 3.11+：

```
pip install -r requirements.txt
```

升级方式：解压覆盖，或 `git pull`。`config.yaml` 不在包里，不会被覆盖。
