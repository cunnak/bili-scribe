v0.4.0：自己传 srt + 迭代打磨与版本史 + 字段级 diff

三件事：

1. 无字幕的视频可以自己传一份 srt：传了就用它（平台字幕让位但如实报明），
   自动探测编码、回执当场给、两条错配校验只警告不阻止、用完即删。
   解析走线程池——5 MB 的 srt 要 0.5-0.8 秒，跑在事件循环上会卡住进度轮询。

2. 迭代打磨：不满意就写一句要求，再改一版，旧版都留着。
   形态是「素材 + 上一版 + 本次要求」，复用预读（4 小时视频省 32,663 tokens / 38%）。
   素材笔记只进内存（可重建），版本史必须落库（不可重建）。
   回退＝把那一版抄成新的当前版，不调模型、零消耗。

3. 字段级 diff：模型自述的「改动说明」实测会不准，所以再算一行「实际改动」——
   把相邻两版逐字段比一遍（纯本地、零成本）。三种状态分开：没比过 / 比过没变 /
   逐字段变了。只报内容字段，列表额外说"有几项内容不同"。
   界面加了「展开全部差异」开关（悬停太容易被忽略）。

修掉的 bug：
- 帧缓存竞争：两次采集共用 frames/<aid>，主任务迟到的收尾会删掉迭代正在写的目录，
  偶发 FileNotFoundError（复现率约 1/6）。改成每次采集独占目录、谁建谁删。
- 要求被质量流程覆盖：约束现在同时贴在批判与修订两轮上。
- 报错丢文件名：错误里带出最后两帧的「文件:行号 函数」。
- 缓存失效的理由只说"重启过"，而缓存满被挤出去也会走同一分支。
- escapeHtml 不转引号，而它的结果会进 title="..."。
- 预读缓存上限的依据错了三个数量级（"几百 MB" vs 实测 0.77 MB），20 → 200。

测试：32 离线 + 35 HTTP + 131 前端，全部通过。
新增的回归用例都先在旧实现上跑一遍确认会失败（跑不挂的守护用例等于没写）。
