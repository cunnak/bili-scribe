## 这个版本解决什么问题

**以前跑过的东西，现在能找回来了。**

每跑一条视频，结果只活在那个任务里。关掉窗口，它就剩下数据库里一段没人读的 JSON——想看"上个月那条讲得挺好，当时怎么说的"，没有入口。

这一版补的就是这个入口。

## 新增「历史」

顶栏多了一个「历史」，跟「设置」并排，上面带着条数。点开是个两栏浮层：左边跑过的每一条，右边选中那条的摘要。

**它不重新问模型。** 后端只查索引字段——标题、UP 主、BV 号、状态、时间、版本数、角色、一句话结论，一律不碰正文那几块大文本。实测同一个库：索引 24 KB，全文 618 KB，差 26 倍。翻历史不该为了一条摘要把整个库读进内存。

列表里能搜：标题、UP 主、BV 号、结论都能筛。点一条看右边摘要，**双击标题直接打开**，或者点「在工作区打开」把那一版原样调回来继续改。

想重跑同一支视频就点「重新总结」——它只把 BV 号填回输入框，**不会立刻重跑**，因为同一支视频再跑一次是要花钱的。

两个刻意的取舍：

- **失败的任务留在列表里，标红。** 没人喜欢在历史里看见一条红的，但记录丢了比记录难看严重得多——尤其是失败那条，往往正是"我当时到底卡在哪"的答案。
- **「还没有版本」和「第 0 版」是两件事。** `current_version` 为 `null` 表示这条任务一个版本都没产出（中途失败），不是"第 0 版"。这条是被测试抓出来的：原来的写法 `row.get("current_version") or 0` 会把两者混成一个，界面上就出现"第 0 版"这种不存在的说法。

## 角色选择搬到顶栏

原来它藏在设置抽屉的「大模型」分组末尾，改一次要走三步。现在跟「设置」并排，点开选一个，**下一次**总结生效。

放在顶栏是因为它属于"这一次想怎么写"，跟填 `api_key` 不是一类事，也确实被频繁换——同一支视频用「标准」过一遍再拿「文稿编辑」扩写，是很常见的用法。

后端为此新增 `POST /api/role`，**只改 `llm.role` 一个字段**，刻意不复用"保存整份设置"那条路：那条要求把明文 `api_key` 再交一遍，为了改一个下拉框让密钥多走一次请求体是白送的暴露面，而且任何字段填错都会连带覆盖别的配置。写盘失败时会把内存里的角色回滚——否则界面显示新角色、重启又变回旧的，会被当成玄学 bug。

## 顺手修的几处

**右键菜单。** 上一版加了 `AreDefaultContextMenusEnabled`，但那只是"默认菜单可用"；真正拦着粘贴的是 `AreBrowserAcceleratorKeysEnabled`——不打开它 `Ctrl+V` 也不工作。两个都要开，且不能顺手把 DevTools 一起打开。

**对比度。** `--dim` 从 `#4A5250` 提到 `#6B7672`，对背景从 2.39:1 到 4.08:1。原来那一档用在标题下的元信息行和版本面板的差异说明上——元素在、JS 也对，只是融进背景里了。

**历史列表会顶出面板。** grid 子项默认 `min-height:auto`，`overflow-y:auto` 不生效；要同时给 `minmax(0,1fr)` 和 `min-height:0`。

**点历史列表任意一行会把整个浮层关掉。** 点行会重绘列表，被点的按钮随即脱离文档，事件冒泡到 document 时 `closest("#hist-pop")` 对游离节点返回 `null`，被误判成"点了外面"。两处监听器都加了 `document.contains(e.target)` 守卫。**这个 bug 在 161 项测试全绿的情况下依然存在**——测试里点的是同一个引用，真实浏览器里 DOM 已经换了。

## 测试

```
python tests/smoke_test.py     # 38 项离线 + 46 项 HTTP
node tests/frontend_test.js    # 171 项前端
node tests/probe_http.js       # 源码版端到端
python tests/probe_exe.py      # 打包产物实机验收
```

前端从 100 项加到 171 项，HTTP 从 35 加到 46。新增的都是**行为断言**，不是"源码里有没有这段字符串"。上面两个真 bug 都是写测试时抓出来的，不是事后补的用例。桌面桥的 `list_history` 也补了——那条路不经过 HTTP 路由表，漏了在源码版永远暴露不出来。

## 安装

**桌面版**：下载 `bili-scribe.exe`，和一份 `config.yaml`（填上自己的 `llm.api_key`）放在一起，双击。

**源码版**：`python run.py`，仍然有 HTTP 服务与 `127.0.0.1:8818`。

两种形态共用同一份 `~/.bili-scribe/`（任务历史、版本史、登录凭据原样沿用，无需迁移）。历史功能读的就是这份已有的库，**升级后立刻能看到以前所有记录**。

---

**升级后先看窗口标题或底栏版本号是不是 `0.6.0`。** 桌面版更直接——exe 里冻的就是打包那一刻的代码，改了源码不重打包，版本号不会变。
