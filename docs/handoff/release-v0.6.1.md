## 这个版本解决什么问题

**一个 exe 就能发给别人用，不用附带任何配置文件。**

上一版已经能单文件运行，但「发给对方」这件事还有个隐藏的坑：程序找配置的顺序是「exe 旁边 → 用户目录」，两个位置都没有时会默认选 exe 旁边。便携版没问题，可是对方把 exe 拖进 `Program Files\`、或者从压缩包里直接双击（解压在只读的临时目录），那地方根本写不进去。于是他认真填完 `api_key` 点保存，收到的是：

```
配置写入失败：[Errno 13] Permission denied: '...\config.yaml.tmp'
```

看着像程序坏了，其实只是落脚点选错了。这一版修的就是它。

## 配置自己找写得进去的地方

两个位置都没有现成配置时，不再无脑取第一个，而是**挑第一个真能落盘的**：

- exe 旁边可写 → 还用那儿（便携版：整个目录拷走就能带走配置）
- exe 旁边不可写 → 退到 `~/.bili-scribe/config.yaml`（装机版：配置属于这个用户，不属于这个程序文件）
- 某处已经有配置 → 它说话，压过上面的可写性判断

判据是「目录存在且真的能建文件」——实际建一个探针文件再删掉，不用 `os.access`。Windows 上它主要看只读属性，对 ACL 不可靠，而这里要回答的恰恰是「到底能不能写进去」。

## 发给对方要注意什么

**只发 exe。** 28 MB，单文件，对方不用装 Python，双击开窗，在设置页填他自己的 `api_key`、扫码登他自己的 B站 账号。

**不要把你那份 `config.yaml` 一起发**——里面有你的 key。我扫过这两个产物，都是干净的：exe 里没有任何 `sk-...` 形态的字符串，源码 zip 的 86 个文件里也没有 `config.yaml` 和密钥。

对方那边唯一可能要额外装的是 **WebView2 运行时**：Win10 1803 以上和 Win11 都自带，只有 LTSC 版和一些很老的机器会缺。缺的表现是窗口弹不出来，装一下微软官方的 WebView2 Runtime 就行。

## 顺手改的

README「分享给别人」那一节原来写的是「把 exe 和一份 config.yaml 发过去」——那是会让对方拿到你密钥的说法，改掉了。

**实测验证**：exe 单独拷进一个空目录启动，窗口正常（标题 `bili-scribe 0.6.1`），界面渲染完整，历史 78 条照常读出来——数据都在 `~/.bili-scribe/`，与 exe 放在哪儿无关。

测试：39 离线 + 46 HTTP + 171 前端，全部通过。
