v0.4.2：界面上看得见的版本号

起因是一个不报错、只让人困惑的处境：「文档里说有，我这没有」——多半是本地那个进程
还是旧代码（v0.4.0、v0.4.1 两次修复都撞在这个上），而**你没有任何办法自己确认
它到底跑的是哪一版**。

这一版把这件事变成一眼可见：

- **页面底部常驻一行** `bili-scribe 0.4.2`。
- **启动横幅也印版本号**（控制台窗口第一行），`python run.py --check` 同样。

版本号只有一处定义（`bili_scribe/__init__.py`）：`/api/config` 把它带给前端，
**前端不另抄一份**——抄一份就会出现两个都会过期的数字，而过期的那个往往正摆在界面上。
离线测试里那条断言是"config 里的 version 必须等于包版本"，这样它不可能漂；
前端用例里夹具故意用一个不存在的版本号 `9.9.9-探头`，前端要是自己写死了一个数字就会露馅。

连不上后端时它**不猜**：直接写「未连上后端，版本未知」。这一行本身就是"页面有没有
连上后端"的第二个证据。

README 的排障一节因此多了一条置顶：「先看页面最下面那行版本号」，并给出处置——
版本对不上就重启进程（Python 不会热加载，`git pull` 之后尤其要重启）。

测试：33 离线 + 35 HTTP + 134 前端，全部通过。
