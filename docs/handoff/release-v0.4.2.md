## 这个版本解决什么问题

一个不报错、只让人困惑的处境：**「文档里说有，我这没有」。**

上一版发完我就发现这件事有多容易发生——`v0.4.0`（帧缓存竞争修复）和 `v0.4.1`（超强思考模式总结）两次发版，你本地那个进程都还是旧代码。而**你没有任何办法自己确认它跑的是哪一版**：界面上不显示版本号，`/api/config` 里的 `version` 也没露出来。于是"发布成功"和"你那里生效了"之间那道缝，只能靠人记得去重启，没有任何地方会提醒你。

## 现在它一眼可见

- **页面底部常驻一行**：`bili-scribe 0.4.2`
- **启动横幅也印**（控制台窗口第一行）：`bili-scribe 0.4.2 —— B站视频内容总结（本地自用）`，`python run.py --check` 同样

## 它是怎么做的（以及两个刻意的决定）

**版本号只有一处定义**：`bili_scribe/__init__.py`。`/api/config` 把它带给前端，**前端不另抄一份**。

这不是洁癖：抄一份就会出现两个都会过期的数字，而**过期的那个往往正摆在界面上**——那时候你相信的是界面上那个，于是"明明升级了却没有新功能"变成一件解释不通的事。两条用例专门守这一点：

- 离线：断言 `/api/config` 里的 `version` **必须等于包版本**（只断言"字段存在"是不够的——字段存在但写死一个旧数字，是最坏的情况）。
- 前端：夹具故意用一个**不存在**的版本号 `9.9.9-探头`，页脚必须把它原样显示出来；同时断言前端源码里没有形如 `bili-scribe 1.2.3` 的硬编码，前端要是自己写死了一个数字就会露馅。

**连不上后端时不猜。** 页脚直接写「未连上后端，版本未知 —— 请从 http://127.0.0.1:8818/ 打开本页」。显示一个"看起来正常"的版本号会掩盖真正的问题；这一行顺带成了"页面有没有连上后端"的第二个证据（第一个是顶部那条红横幅）。

## 排障一节多了一条置顶

README 的「出问题先看这里」现在从这一条开始：**先看页面最下面那行版本号**。

- **"文档里说有，我这没有"** → 先看这一行。多半是本地这个进程还是旧代码：控制台横幅的版本号对不上，就是没重启。停掉旧进程再起一次，代码就换过来了——**`git pull` 之后尤其要重启，Python 不会热加载**。
- **它写着"未连上后端"** → 页面不是从 `http://127.0.0.1:8818/` 打开的，或者后端已经退出了。

## 安装

下载下方的 `bili-scribe-0.4.2.zip`，解压后按 `README.md` 操作。包内**不含**任何凭据、数据库或本机配置——打包脚本自检一次，`scripts/verify-package.py` 再用另一套判据复核一次（本次：敏感文件名 0 命中；凭据、本机路径 0 命中；包内唯一出现的视频号是文档占位符 `BV1xx411c7mD`；包内版本与工作区一致）。

**升级之后记得重启进程**，然后看一眼页面底部那行版本号对不对——这一版就是为这件事加的。

需要 Python 3.11+。
