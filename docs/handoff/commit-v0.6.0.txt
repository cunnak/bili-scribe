v0.6.0：跑过的东西不会再消失

以前每跑一条视频，结果只活在那个任务里。关掉窗口，它就只剩下数据库里一段没人读的
JSON——想看"上个月那条讲得挺好，当时怎么说的"，没有入口。这一版补的就是这个入口，
顺带把「角色」从设置抽屉里搬了出来。

新增「历史」

顶栏多了一个「历史」，跟「设置」并排，上面带着条数。点开是一个两栏浮层：左边是跑过
的每一条，右边是选中那条的摘要。

它不重新问模型。后端新增的 list_task_index 只查索引字段——标题、UP 主、BV 号、状态、
时间、版本数、角色、一句话结论，一律不碰 summary_json 那几块大文本。实测同一个库：
索引 24 KB，全文 618 KB，差 26 倍。翻历史不该为了一条摘要把整个库读进内存。

列表里能搜：标题、UP 主、BV 号、结论都能筛。点一条看右边摘要，双击标题直接打开，
或者点「在工作区打开」把那一版原样调回来继续改。想重跑就点「重新总结」——它只把 BV
号填回输入框，不会立刻重跑，因为同一支视频再跑一次是要花钱的。

两个刻意的取舍：

一、失败的任务留在列表里，标红。没人喜欢在历史里看见一条红的，但记录丢了比记录难看
严重得多——尤其是失败那条往往正是"我当时到底卡在哪"的答案。

二、「还没有版本」和「第 0 版」是两件事。current_version 是 null 表示这条任务一个版本
都没产出，不是"第 0 版"。写成 `row.get("current_version") or 0` 会把两者混成一个，
界面上就会出现"第 0 版"这种不存在的说法。这条是被测试抓出来的，不是想出来的。

角色选择搬到顶栏

原来它藏在设置抽屉的「大模型」分组末尾，改一次要走三步。现在跟「设置」并排，点开选
一个，下一次总结生效。放在顶栏是因为它属于"这一次想怎么写"，跟填 api_key 不是一类事，
也确实被频繁换——同一支视频用「标准」过一遍再拿「文稿编辑」扩写，是常见用法。

后端为此新增了 POST /api/role，只改 config.yaml 里的 llm.role 一个字段，刻意不复用
保存整份设置那条路：那条要求把明文 api_key 再交一遍，为了改一个下拉框让密钥多走一次
请求体是白送的暴露面，而且任何一个字段填错都会连带覆盖别的配置。写盘失败时会把内存里
的角色回滚——否则界面显示新角色、重启又变回旧的，会被当成玄学 bug。

抽屉里留了一个 hidden 的 llm.role。删掉它的话，保存设置时这个字段缺席，Pydantic 的
LlmPatch.role 默认值 "standard" 会把角色悄悄重置回默认——保存一次设置，角色就白换了。

顺手修的几处

- 右键菜单。上一版加了 AreDefaultContextMenusEnabled，但那只是"默认菜单可用"；真正
  拦着粘贴的是 AreBrowserAcceleratorKeysEnabled——不打开它，Ctrl+V 也不工作。两个都
  要开，且不能顺手把 DevTools 一起打开。
- 对比度。--dim 从 #4A5250 提到 #6B7672，对 --bg 从 2.39:1 到 4.08:1。原来那一档用在
  标题下的元信息行和版本面板的差异说明上——元素在、JS 也对，只是融进背景里了。
- 历史浮层的列表会顶出面板。grid 子项默认 min-height:auto，overflow-y:auto 不生效；
  要同时给 minmax(0,1fr) 和 min-height:0。
- 点历史列表任意一行会把整个浮层关掉。点行会重绘列表，被点的按钮随即脱离文档，事件
  冒泡到 document 时 closest("#hist-pop") 对游离节点返回 null，被误判成"点了外面"。
  两处监听器都加了 document.contains(e.target) 守卫。这个 bug 在 161 项测试全绿的情况
  下依然存在——测试里点的是同一个引用，真实浏览器里 DOM 已经换了。

测试

前端 100 → 171 项，后端 35 → 46 项 HTTP、37 → 38 项离线，合计 255 项。

新增的都是行为断言，不是"源码里有没有这段字符串"。上面两个真 bug（current_version
被 or 0 吞掉、点行关面板）都是写测试时抓出来的，不是事后补的用例。桌面桥的
list_history 也补了——那条路不经过 HTTP 路由表，漏了在源码版永远暴露不出来。

版本号从 0.5.0 提到 0.6.0。0.5.0 那批（桌面化 + 分层 + 前端重写 + 笔记缓存）从未发布
过，但历史功能是它之后单独长出来的一块，值得单独一个版本号，而不是让它悄悄混进去。
