v0.7.0：加一套浅色皮肤，顺手把颜色收干净

起因是「能不能换个配色」。看起来是个改 CSS 的小活，翻下去发现做不了——现有那套
配色里，变量只覆盖了一半，剩下大量颜色是**写死的字面量**：

    rgba(216,242,75,.45)   7 处     #C8CFCB   6 处
    rgba(216,242,75,.4)    5 处     #0A0B08   5 处
    rgba(216,242,75,.07)   4 处     #E4FA6B   2 处   #0A0C0D  2 处
    rgba(216,242,75,.42)   3 处     ...

全量数：`<style>` 里 79 处字面量、40 种不同写法。这些不搬进变量，换肤就只能换一半：
按钮换了、提示条还是橙的；卡片换了、分隔线还是白的。所以这一版真正的活是**先按用途
（不是按数值）把这 79 处收进变量**（颜色变量 13 → 26 个），再谈第二套皮肤。

## 三个不能照搬的地方

浅色那套的配色参考明日方舟线下展（INTERACTIVE EXHIBITION）那批海报：近纯白底、大量
留白、细黑描边的小图标，颜色只用在色块、圆点、标签这种小面积上。直接「把深色反过来」
会出三个问题，都是量出来的，不是猜的：

1. **荧光黄绿当文字在近白底上只有 1.54:1**，读不清。所以拆两支：`--acid` 仍用亮黄绿，
   只做色块、进度条、按钮底（上面压深字 12.2:1 没问题）；文字与 1px 细线另走
   `--acid-tx`（深橄榄 #5F6E00，5.4:1）。
2. **橙色同理**。`#FF6B35` 浅底 2.71:1，不合格，换洋红 `#C4186F`（5.4:1）——正好也是
   海报三色之一。`--paper #E8E2D4` 更极端，1.24:1 等于消失，换 #2A3134（12.7:1）。
3. **叠层方向必须反转**。深色皮肤里 `rgba(255,255,255,.035)` 是「提亮一点点」；白底上
   照搬等于什么都没画。引入 `--ink-rgb`（深色 255,255,255 / 浅色 0,0,0），7 处 hover、
   2 处网格、各处描边改成 `rgba(var(--ink-rgb),...)`，换肤时整组自动反转。同理
   `--shade-rgb` 给阴影、`--scrim-rgb` 给遮罩——浅底上 0.62 的黑影会脏成一片。

## 深色皮肤逐像素没变

这是硬要求：加皮肤不该让老用户发现界面有任何变化。机械验证，不靠肉眼——把改动前后的
`index.html` 剥掉两套变量块和新增的 `.sk` 规则、展开所有 `var()`、规范化空白与大小写
之后逐字比对：`IDENTICAL`，归一化长度都是 25722 字符。

第一版合并 alpha 时踩了坑：把 `.45/.4/.42` 合成一个 `--acid-line`、`.06/.055/.03` 合成
一个 `--acid-wash`。肉眼几乎看不出，但它确实改了深色皮肤的像素值，违反上面那条。回退
重做，按用途拆而不是按"看起来差不多"合并。

## 桌面版连标题栏一起换

标题栏和启动底色不在网页里，是 `desktop.py` 拿 `DwmSetWindowAttribute` 单独设的。不跟
着换有两个难看的地方：

- **启动闪一下**：窗口出现到页面画完之间有一段空白，底色对不上界面 `--bg` 就闪出另一种色
- **浅色皮肤挂一条深色标题栏**：所以改成按底色亮度（`0.299r+0.587g+0.114b < 128`）自动
  选深色还是浅色文字，换肤时顺带重刷，不用重启

## 皮肤名写错当场报错

`ui.skin` 填了个不存在的值（比如 `exibition`）时，配置加载直接失败并列出可选值。

这个坏法特别隐蔽：CSS 里没有对应变量块时所有 `var()` 取不到值，界面变成一片白板——
而配置文件本身看着完全正常，日志也没有异常。宁可启动失败让人当场看见。

## 切换只写一个字段

跟「总结角色」同一条路子：`POST /api/skin` 只改 `config.yaml` 的 `ui.skin`，不走保存
整份设置那条路（那条要把明文 `api_key` 再交一遍）。写盘失败时内存里的值回滚，否则界面
显示新皮肤、重启又变回旧的，会被当成玄学 bug。

## 写测试时抓到的两个真缺陷

1. **`pickSkin()` 里赋值和渲染顺序写反了**：chip 读的是 `S.cfg.ui.skin` 而不是 `S.skin`，
   顺序反了会出现「界面已换、chip 仍显示旧名字」的自相矛盾状态。
2. **前端测试的假后端缺 `set_skin`**：真后端有、假后端没有。这类漏法在源码版永远暴露
   不出来——测试里所有调用都喂给假后端，它只能证明"界面按约定办事"。
3. **`/api/skin` 这条真实路由此前一次都没被走过**：源码版与前端测试都只验了"界面按约定
   调了接口"，没人验"接口真的写进了文件"。补了三条 HTTP 断言：写盘、未知皮肤 400 并列出
   可选项、保存整份设置不会把刚选的皮肤带回旧值。

前端测试新增 39 条，全是行为断言。其中一条值得单说：**切回默认皮肤时 `data-skin` 必须
是 `null` 而不是 `"ark"`**——写成 `"ark"` 会让两套配色同时命中，谁赢取决于选择器优先级，
而优先级是会随改动漂移的。

## 打包后才暴露的一个致命 bug

桌面版把当前皮肤告诉页面的方式原来是拼查询串：`index.html?skin=exhibition`。网页版没问题，
但桌面版加载的是 `file://` URI——**查询串会被 WebView2 当成文件名的一部分**，它去找一个
叫 `index.html?skin=exhibition` 的文件，找不到，窗口里显示的是「未找到文件 / 
ERR_FILE_NOT_FOUND」。也就是说这个 bug 会让桌面版**完全打不开**，而源码版一切正常。

更麻烦的是探针判它"通过"了：原判据是"窗口画出了东西"+"截图颜色数够多"，那张报错页白底、
蓝紫大叉、彩色浏览器徽标，颜色数上万，两条判据全满足，探针还打印了「exe 能启动、能开窗、
能渲染」，退出码 0。看截图才发现窗口里根本不是我们的界面。

改法两处：①改用 hash（`file://...#skin=exhibition` 合法，片段不参与文件解析；网页版仍
支持 `?skin=`，两条都认）；②探针不再数颜色，改成查**我们自己的品牌色**——顶栏那块
`--acid` 荧光黄绿斜块，报错页里不可能有。这里又踩一次：第一版按 RGB 逐通道比写死的
`#D8F24B`，真截图里那块是 `(214,253,2)`（DWM 合成叠了色彩管理，蓝通道被改写），硬比
假红；改成按色相判才稳。

## 实测验证

- 深色皮肤逐像素不变：剥变量块 + 展开 `var()` + 规范化后逐字比对 → `IDENTICAL`
- 浅色皮肤对比度全项达标（浅底 #FAFAF7 / 卡片 #FFFFFF）：正文 17.09、次要正文 9.51、
  muted 5.51、dim 3.55、文字用黄绿 5.90、洋红 5.42、`--on-acid` 压亮黄绿 12.23
- 真机截图逐区核对：真服务 + headless Chrome 各截 1440×900 全页，两套皮肤各一份，逐区
  看了顶栏斜块与斜纹、刻度尺 64 根、进度条分段、卡片斜切角与 `01/02` 编号、提示条、
  右栏版本面板与 token 统计、底栏、皮肤浮层、设置抽屉。浮层和抽屉默认关着，另写了两个
  探针页把它们打开再截（抽屉是 `translateX(101%)` + `.22s` 过渡滑入，headless 的
  `--virtual-time-budget` 不推进 CSS 过渡，第一次只截到一条缝，得先关掉过渡）
- `--ink-rgb` 反转生效：浅底上刻度尺、网格、行悬停全部可见，没有消失
- 打包 exe 真跑：dist/bili-scribe.exe（28.2 MB）在系统临时目录启动，窗口标题
  `bili-scribe 0.7.0`，截图品牌色占 0.65%，exe 旁边没有多出文件

测试：40 离线 + 49 HTTP + 210 前端，全部通过。
