v0.5.0：它不再是个网页，素材也不再重复买

三件事，都是「用起来别扭」那一类。

一、它一直是个网页。得开一个控制台窗口看着服务日志，再切到浏览器标签页里操作；
关掉控制台就把自己弄挂了。现在它是一个独立的应用窗口，双击就开，有任务栏图标。

二、素材被重复买了好几遍。同一份素材的预读结果，只要换个任务重跑就得重买一次。
真实账本里有个视频被重开成两个任务，两次各付约 13 万 prompt tokens 的完整预读，
第二遍完全是白花。现在这份笔记按内容寻址缓存，同一个视频再跑一次一分不花。

三、界面太简陋。单页 HTML 里 207 行 CSS、五个编号卡片竖着堆。现在重写成一个工作面。

架构上多了一层壳，三层关系没变：

    desktop.py（窗口）      main.py（HTTP 路由，只做传输）
            └──────────────┬──────────────┘
                      app/service.py（业务，1382 行）
                                ↓
                        core/ → infra/

桌面版不再监听端口，界面直接调 Python 函数，进度由后端主动推给界面。一个两分钟的
任务，以前页面要问七十多次「好了没」，现在 0 次——它不是慢，是白做。

素材笔记用内容寻址：sha256(recipe + source_label + body)，recipe 里含
max_input_chars / chunk_size / chunk_overlap 三个会影响产出的参数，参数一改 key 就变，
不可能命中过期笔记。只在 chunks > 1 时写缓存（短素材根本不预读）。这是零损优化：
命中省一段预读，未命中退化成本来的行为，写缓存失败也只是下次重跑——没有任何一种
失败会让产物变差，所以默认开启、不设开关。

配置查找顺序也改了：以前只认工作目录，而 exe 双击启动时工作目录不一定是 exe 所在
目录，按当前目录找会让人把配置写到莫名其妙的地方——表现就是「明明保存了下次打开
又是空的」。现在认 exe 旁边 → ~/.bili-scribe/config.yaml，exe 旁边的优先。

## 顶栏角色选择

顺手把角色从设置抽屉里搬出来，做成顶栏里跟「设置」并排的独立控件：点开是浮层，
列出八个角色，当前项高亮。新增 POST /api/role，只带 role 一个字段。

刻意不复用 put_settings：那条路要求提交整份设置（含明文 api_key），为一个下拉框
让密钥多走一遍请求体是白白的暴露面，而且任何字段填错会连带覆盖别的配置。
写盘失败会回滚内存值再报错——否则界面显示新角色、重启又变回旧的，会被当成玄学 bug。

抽屉里原来的下拉框改成隐藏字段而不是删掉：删掉的话保存设置时 llm.role 缺席，
Pydantic 的默认值 "standard" 会把角色悄悄重置。

桌面桥 desktop.py 也要同步暴露 set_role——两边共用同一份 index.html，网页版能切、
桌面版点了没反应，而且从界面上完全看不出来。这条已经写成回归用例。

## 三处界面可见度修复

元信息行和版本面板的差异说明原来用的 --dim 只有 2.39:1 对比度，提到 #6B7672
后是 4.08:1（panel 上 3.86:1）。输入框右键粘不进去是 pywebview 把两样都关了：
AreDefaultContextMenusEnabled（右键菜单）和 AreBrowserAcceleratorKeysEnabled
（Ctrl+V 的总开关）。第一版只补了前者，用户回来说「还是粘不进去」——两条必须
一起测，只测一条的话漏掉另一条同样能全绿。

## 测试

    python tests/smoke_test.py     # 38 项离线 + 40 项 HTTP
    node tests/frontend_test.js    # 125 项前端（jsdom，真 DOM 真事件）
    node tests/probe_http.js       # 源码版端到端
    python tests/probe_exe.py      # 打包产物实机验收

前端测试是全部重写的。旧的 134 项做的是「读源码 → 正则抠出 script → 在 DOM 桩里
求值 → 断言源码里出现过某段字符串」，它一直在报 PASS，测的却是拼写。现在换成
jsdom：断言的是行为（点了按钮会发生什么、界面变成什么样）。

三条守底线的还在：页面里没有 <input type=file>、颜色对比度实际算出来（正文 ≥ 4.5:1）、
以及源码版那张 HTTP 路由表与后端逐个对账。路由表那条补得很值——补它的时候顺手
抓到一个真 bug：testLlm() 多包了一层壳，后端收的就是那一层内部的字段，于是 422 报
Field required，错误信息指着字段名、不指着多出来的那层壳。它从来没被任何测试碰过。
