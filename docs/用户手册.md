按功能写的操作手册。每一步都写：**在哪点、看到什么、失败怎么办**。

## 窗口长什么样

```
┌──────────┬───────────────────────────────────────────────────────┐
│ 新建任务 │  页面标题 · 一句话说明              [皮肤] [进行中 N] │ 48px
│ 素材库   │                                                       │
│ 切片台   │                                                       │
│ 合并     │                    页面内容                           │
│ 发布     │                                                       │
│          │                                                       │
│ 设置     │                                                       │
├──────────┴───────────────────────────────────────────────────────┤
│ 下载 2 · 转录 1 · 导出 0        磁盘 剩余 218 GB     v0.1.0      │ 28px
└──────────────────────────────────────────────────────────────────┘
```

- **左栏**：六项 + 底部设置（新建任务 / 素材库 / 字幕 / 总结 / 切片台 / 合并 / 发布）。现在的页面左边有一道 3px 竖条（主题色）。
- **顶栏**：当前页标题、搜索框（素材库/设置里有用）、皮肤开关、进行中的任务数（点开看详情）。
- **状态栏**：三类任务的排队数、磁盘剩余、版本。依赖缺了会在版本旁标出来。
- 想左栏收窄：底部「折叠」。收成 56px 图标条，下次打开还是收着的。

## 一、新建任务（下载）

**它是唯一往库里加东西的入口**（另一个是素材库的「导入本地」）。

1. 在输入框粘贴链接。支持：`BV1xx411c7mD`、`av12345`、`b23.tv/xxxx`、番剧 `ep123456`、剧集 `ss1234`、媒体 `md1234`，带 `?p=3` 也能认。
2. 回车或点「解析」。这一步**只读信息，不会下载**：
   - 单稿 → 显示标题、UP 主、时长、封面
   - 分P → 列出每一集，默认全选
   - 合集/番剧 → 先列子项，再选集
3. 选画质（`4K / 1080P / 1080P+ / 720P`）。没有对应权限时会**降级并在日志里写明实际画质**，不会静默给个低清。
4. 点「开始下载」。下载在后台跑，状态栏能看到进度；页面上会跳去素材库。

目录长这样（可在设置里改 `download.dir_template`）：

```
{media_root}/{UP主}/{合集?}/{视频标题}/{P01_分P标题?}/{视频标题}.mp4
```

源视频文件用视频标题命名，多P 是 `主标题 - 分P标题.mp4`，在资源管理器里能一眼看出哪个文件是哪一集。同目录下的 `source.wb.json` 是侧车记录，**名字固定不跟着标题变**——程序靠它认目录。

同一集重复下载不会再来一遍：已有文件且侧车记录对得上，直接复用。

**失败怎么办**

| 提示 | 意思 | 下一步 |
|---|---|---|
| `AUTH_REQUIRED` / 要求登录 | 没登录或 cookie 过期 | 在 bili-scribe 里重登一次（两边共用登录态） |
| `BILI_ERROR` + 地区限制 | 这个视频要大会员/限制地区 | 换源；不是程序能绕的 |
| `NETWORK` | 网络抖动 | 会自动退避重试 3 次；还不行就手动「重试」 |
| `DISK_FULL` | 空间不够（要求剩余 ≥ 2×预估+5GB） | 清盘或改 `storage.media_root` |
| `PROCESS_FAILED` | yt-dlp/FFmpeg 报错 | 看详情里的原始输出；多半是流变了，更新 yt-dlp |

已经下了一半就取消的，`.part` 会被删掉，不留半成品。

**下不动时换 BBDown（手动兜底）**

yt-dlp 有时会被大会员/风控卡住，BBDown 走的是另一条路。程序**不会自己换**，必须你点头：

1. 把 `BBDown.exe` 丢进仓库的 `tools/` 目录（或在设置 → 下载的 `download.bbdown_path` 里填绝对路径）。
2. 设置 → 下载 下面有一行「后端」状态（`yt-dlp` / `BBDown` 各一行），点「重新检测」刷新。
3. 新建任务页底部「最近下载」里，失败的那条旁边会出现「用 BBDown 重试」。
   **没检测到 BBDown 时这个按钮不出现**，只有一行说明告诉你去哪儿放。

重试生成的是新任务，失败那一集单独重跑，已经成功的不会重下。父任务当初用的就是 BBDown 的话，
再点「重试」会继续用 BBDown。

## 二、素材库

三栏：左筛选、中列表、右详情。

- **左栏**：来源树——「全部项目 / 合集 / 本地导入 / 未归类 / 其他」，每个分组带数量；点任一分组，右侧只显示这个来源内的素材，再点「全部项目」回到全部。底部还有「缺文件 / 待转录 / 最近导入」三个智能视图和已归档入口。
- **顶部阶段条**：`全部 / 待转录 / 已下载 / 有字幕 / 已转录 / 已总结 / 已切片 / 已合并 / 已发布`。所有计数按当前来源重新统计；点阶段只在这个来源内继续筛，点「全部」回到当前来源全部。
- **中栏**：一行一个项目，72×41 缩略图 + 标题 + 阶段标记。文件不在磁盘上会标红并写「在位 / 缺失」。
- **右栏**：这个项目的全部产物（源视频、音频、字幕、总结、切片、封面）与操作按钮。

常用动作：

| 想干 | 点哪 |
|---|---|
| 转录 | 右栏「开始转录」（阶段是「待转录/已下载」时出现） |
| 改字幕 | 右栏「字幕」，进字幕编辑器 |
| 看总结 | 顶部「总结」（在项目详情里进） |
| 切片 | 右栏「切片台」 |
| 找到文件 | 「打开媒体目录」 |
| 从库里去掉 | 「从库中移除」——**默认不删文件**；勾了「同时删文件」才真删 |
| 加本地文件 | 顶部「导入本地」（不搬文件，只建索引；同名 srt/ass 会被认成字幕） |

**文件缺失**：右栏会出现一条红条，列出不在磁盘上的文件。可以「定位」重新指一个，也可以只删记录。

**搜索**：顶栏搜索框输标题/UP/BV 号，即时过滤。

## 三、字幕编辑器

从素材库右栏「字幕」进，或点左栏「字幕」。左列表、右波形。

- **项目选择**：从左栏进入时，页面顶部有项目条——下拉选项目，搜索框按标题 / UP 名 / BV 号过滤；
  切到别的项目前会先把当前草稿保存好，保存失败就停在原项目并给出提示。
- **在文件夹中显示**：项目条右侧按钮在资源管理器里打开这个项目的目录。

### 看到的

- 顶部：段数、总时长、语言、模型、质检徽标（警告数）
- 左边列表：序号、起止时间、文本。**双击改文本，回车保存**；选中行左边亮一道主题色
- 下面波形：拖动选区间，滚轮缩放；播放头跟着音频走
- 底部工具条：`+1帧 / −1帧`（按真实帧长）、拆分、合并、平移、查找替换、质检、导出

### 能干的事

| 动作 | 怎么用 | 说明 |
|---|---|---|
| 改错字 | 双击文本 → 改 → 回车 | 自动保存（停手 0.7 秒落盘），Ctrl+Z 撤销 |
| 拆分 | 光标放位置 → 「拆分」 | 时间按当前播放头切 |
| 合并 | 选两段相邻 → 「合并」 | 不相邻会拒绝（中间那段会被吃掉） |
| 整体平移 | 「平移」输入毫秒 | 全片偏早/偏晚时用 |
| 查找替换 | 「查找 / 替换」 | 支持正则，替换里能用 `$1` |
| 质检 | 「质检」 | 空段、负时长、过短、过长、超字数、重叠、大空隙 |
| 优化（LLM） | 「优化」 | 让模型改口语、断句、标点；**出来的是 diff 预览，点应用才写库** |
| 翻译 | 「开始翻译」 | 先出草稿，确认后才落 `subtitle.{lang}.srt` + 双语 ASS |
| 导出 | 「导出字幕」 | SRT / ASS / VTT；ASS 以 720P 为基准等比缩放 |
| 波形 | 看到的是真实音频峰值 | 峰值缓存在项目目录 `peaks.json`，随时间戳失效 |

**质检规则**（`MAX_CHARS_PER_LINE=22`、`MAX_SEGMENT_MS=12000`、`MIN_SEGMENT_MS=400`）：
`empty` / `negative`（错误）/ `too_short` / `too_long` / `too_many_chars`（>44 字）/ `overlap`（双段错误）/ `big_gap`（>60 秒，提示级）。

### 填了地址和密钥，还是报 403 / 「被网关拒绝」

先看报错里的 detail：

- 出现 `Cloudflare` / `1010` / `blocked access based on your browser signature`：
  服务端前面的 CDN 把客户端当成机器人拦了，**跟你的 key 没关系**。程序内置的 UA 已经是浏览器 UA，
  所以先走下面两条；仍然 1010，说明这家除了 UA 还看别的指纹：
  1. 在「上下文与长素材 → 代理」填本机代理（例如 `http://127.0.0.1:7897`），走代理出口；
  2. 或换一个更新的浏览器 UA 填进「请求 UA」。
  两项改完都要重启程序才生效。

有些网关还要私有请求头：opencode 的 `x-opencode-session` 程序会自动补；Azure 的 `api-version`、自建网关的 `x-tenant`
要自己填，入口是「上下文与长素材 → 额外请求头」，一行一个「名字: 值」。
- 没有 Cloudflare 字样、就是 403：那张卡上的 key 可能没有该接口/模型的权限，换 key 或换模型再试。

401 才是「key 不对或没有权限」，两者的处理方式不同，别混。

### 模型服务商（一家一张卡）

设置 → 模型，一张卡就是一家服务商：**名称、协议、API 地址、API Key、模型列表**。

- **加一家**：点「添加服务商」→ 填地址与 key → 点「获取可用模型」，弹出这家账号能用的模型清单
  （已配置的默认勾上），勾完点「添加所选」→ 点「测试连接」，按钮下面会直接回「连上了：模型 · 延迟」或具体原因。
  懒得连网就跳过获取，直接在「模型」里输模型名回车。
- **获取可用模型**：走 `GET {API 地址}/models`，只读不写，密钥只在请求头里。拿不到就说明该地址不支持这个接口，
  或密钥没填——弹窗里会写原因，手填模型名照样能用。
- **换默认那家**：点某张卡的「设为当前」。之后所有没单独指名的任务都用它。
- **只给某类任务换一家**：展开「上下文与长素材」→「任务模型」，
  左边是任务（总结 / 合集总览 / 翻译 / 切片分析 / 文案 / 改写 / 画面精析），
  右边填 `服务商/模型`（如 `kimi/moonshot-v1-8k`）或只填模型名（如 `deepseek-reasoner`）。
  留空＝跟随默认。
- **删一家**：卡片右上角的垃圾桶。只剩一张时按钮不出现——不能把配置删空。
- 密钥只写在本机 `workbench.json`（和 bili-scribe 共用的 `config.yaml` 放同目录），界面只显示尾号；「显示」只是把输入框变成明文，不发请求。
- 两个文件的分工：`config.yaml` 只放 bili-scribe 也认识的设置，扩展设置（服务商、任务模型、目录、切片参数等）在 `workbench.json`。**别往 `config.yaml` 里手加键**——bili-scribe 读到不认识的键会直接起不来。

关于「上下文与长素材」里的几项，改之前先知道代价：

| 项 | 改了会怎样 |
|---|---|
| 深度思考 | 开＝推理过程也吃 `max_tokens`，正文容易空、容易超时；跟随模型最省心 |
| 单次输入上限 | 超过就按分块切开分别总结再合并，调小省 token 但可能切断段落 |
| 分块大小/重叠 | 分块太小会把一句话切断，重叠是为了让跨界的话不被丢 |
| 请求超时 | 长视频总结 + 思考模型要放宽，默认 300 秒 |

**术语表**：设置 → 字幕里维护，一行一条 `源词=目标词`。翻译后会按它强制替换——只对「模型没译、把源词原样带出来」的情况有效，模型自己换了写法管不了（那靠提示词）。

**快捷键**（焦点不在输入框时生效）：`Space` 播放/暂停、`Enter` 编辑选中的段、`Delete` 删段、`Alt+↑/↓` 上/下换段、`←/→` 前后 1 秒（配 `Shift` 为 5 秒）、`S` 拆分、`M` 合并、`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 或 `Ctrl+Y` 重做、`Ctrl+F` 打开查找替换。改文本会自动保存（停手 0.7 秒落盘），没有单独的「保存」键。

## 四、总结

从素材库选一个已转录的项目 → 「总结」。

1. **先选角色**：8 种（如「硬核」「拆解」「科普」…），角色决定语气和结构。
2. 点「重新生成」。等 10~60 秒，右侧出正文：一句话结论、核心结论、怎么论证的、要点、时间线、注意。
3. 不满意：
   - 换个角色重出 → **新的一版**，旧版都在左边「版本」里
   - 或写一句「要点压到三条，别用『赋能』这种词」→ 点「按这个改」，只改该改的地方
4. 每一版都能「恢复」回任意历史版本。
5. 右栏「用量 · TOKENS」：**这一版开销**（输入/输出 tokens、调用次数、耗时、素材预读）和
   **这条视频累计**（按全部版本求和，含总 tokens）。token 显示「—」= 那一版没记录用量
   （早期版本只记了调用次数），不是花了零。

**这是草稿**。界面里没有「自动发出去」，也没有「生成即发布」。

**合集**：左栏切到合集，一次看完多集并给推荐观看顺序（只请求一次，不逐集问）。

**失败**：`LLM_ERROR` / `LLM_AUTH` / `LLM_RATE_LIMIT` / `LLM_TIMEOUT` 都会写明原因。设置 → 模型里有「测试连接」。

## 五、切片台

`生成候选 → 改切点 → 预览 → 导出`，三步都在这页。

### 1. 生成候选

「生成候选」→ 出 5–12 条，每条带分数、时长、理由。分数高的是模型觉得能单独成立的段落。

- 没有 LLM 配置时会走**规则兜底**（按静音切、按时长挑），页面上会明说「兜底」——位置可用，但标题和分数没有内容含义。
- 候选会**吸附**到句子边界（容差 2 秒）并去重（重叠过半只留分高的）。

### 1.1 画面精析（配了 vision 模型才跑）

设置 → 模型 → `tasks.vision` 填了模型名之后，「生成候选」会多做一层：给分数最高的那几条候选
各抽 3 帧画面、算一遍响度，再把帧交给 vision 模型重打分数、改标题与理由。

- **只改分数和文案，不动起止时间**——模型看的是首中尾三帧，没有把"画面好看"换算成毫秒的能力。
- 跑完提示条写「候选已更新（画面精析改了 N 条）」；没跑或跑不了时写原因：
  「没配 vision 模型，跳过画面精析」/「找不到源视频文件，跳过画面精析」。
- 单条精析失败**不会**让整批候选丢掉，只记一条说明，其余照旧入库。

### 2. 改切点

点候选卡片 → 右边检查器：

- 拖时间线两端，或直接改起点/终点；拖动时按 2 秒容差吸附
- `+1帧 / −1帧`：真帧长（探不到 fps 时按 40ms 算）
- 「播放这一段」有 3 秒预卷，方便听切点对不对
- 改过的候选会标「手动改过切点」，并保留模型原值

### 3. 导出

| 选项 | 说明 |
|---|---|
| 画幅 | 原比例 / 9:16 竖屏 |
| 竖屏取景 | 居中 / 模糊背景 / 人脸跟随（画面自带黑边会先自动削掉，避免模糊出黑柱） |
| 字幕 | 不烧 / 硬字幕（烧进画面）/ 软字幕（mov_text，可开关） |
| 速度 | 精确（重编码，切点误差 ≤1 帧）/ 快速（`-c copy`，秒出但切点会偏到关键帧，界面会标偏移量） |
| 音轨 | 背景音乐（可选）/ 音量 / 人声出现时自动压低 / 淡入淡出时长 |

#### 人脸跟随：增强开关与「跟谁」

选「人脸跟随」后，取景区下面会多两件东西：

- **增强跟随**（勾选框）：默认开。开着的时候，一帧里的多张脸会按"同一个人"跨帧归类，
  逐个人算分（出镜时长 40% + 稳定性 25% + 脸的大小 20% + 是否在画面中间 15%），
  默认跟分最高的那位；**镜头切换处不做平滑**（切点前后各留 20ms 的瞬时跳变，
  否则一次切换会被拉成几秒的横移）。
- **跟谁**（下拉框，只在认出 ≥2 个主体时出现）：换人会立刻按已经测好的轨迹重建，
  **不重新抽帧**（重新检测一集 480 秒的片子要一分钟，换个人不该等这么久）。

取消「增强跟随」就退回基础跟随：只跟画面里最大的那张脸，没有主体概念、也没有切点处理。

#### 音轨：配乐、闪避与淡入淡出

导出面板最下面一行是音轨设置：

| 控件 | 说明 |
|---|---|
| 背景音乐 | 点「选音乐」挑本地音频（mp3/wav/m4a 都行）。选完显示文件名，旁边「×」清掉 |
| 音量 | 默认 25%。填 `30` 和填 `30%` 是一回事；`0` 是静音 |
| 人声出现时自动压低 | 默认开。关掉就是配乐一直按固定音量铺着 |
| 淡入淡出 | 默认 200 ms，可填 0 关掉；上限 3000 ms，也会被片长自动收缩（最长不超过片长的 30%） |

闪避不是"拿字幕猜哪里在说话"，是拿**原声的电平**做侧链：原声响了就把配乐压下去
（约 8:1、20ms 起效、300ms 恢复）。所以没人说话的时候配乐是满音量的，
一开口立刻让位——字幕断句不准也不会影响音轨。

几个实际表现：

- 配乐比片子短会自动循环，不用先把配乐剪到片长；
- 片子本身没有音轨时也能加配乐（这时不存在"闪避"，配乐只按音量铺）；
- 同一段切片换配乐或改淡入淡出时，批量导出**会重导**；参数完全一样才跳过；
- 快速模式（`-c copy`）只要动了音轨就会自动转成精确重编码——`copy` 没法混音。

导出完成的任务详情里会多一行说明，例如
「BGM：bgm.wav（30%，人声出现时自动压低）；淡入淡出 200 ms」，看得出这次到底做了什么。
这两条路的结果都写进 `focus.json`，导出时读的就是它——所以检测完再改导出参数不会丢轨迹。

人脸检测需要两个前提，缺了不会卡住你的活，只是退成居中裁切：

- OpenCV 4.x 用自带的 Haar 级联（`haarcascade_frontalface_default.xml`，首次自动下载）；
- OpenCV 5 起没有 Haar 了，改用 YuNet（`face_detection_yunet_2023mar.onnx`，约 230 KB，
  首次自动下载并校验 sha256）。下载走 `media.githubusercontent.com`，国内需要给
  `llm.proxy` 填代理才下得动。

「检测人脸」跑完，取景区下方会写一行状态：轨迹点数、用的哪个检测器、有几处镜头切换没插值、
当前跟的是谁。没检测出脸时写「这段里没检测到人脸，按居中裁切」——这是正常结果，不是报错。

「导出队列」在下方，能看进度、取消、重试失败项。批量导出用「全选 → 导出」，同一参数已导过的会跳过。

**取消**：真的杀进程树，不留半成品文件。

#### 交付到剪辑软件（剪映 / 达芬奇 / 降级包）

导出面板最下面是「交付到剪辑软件」，三个按钮各出一条路：

| 通道 | 给谁用 | 产物 |
|---|---|---|
| 剪映草稿 | 剪映（专业版） | 一个草稿文件夹（`draft_content.json` + `draft_meta_info.json`），有视频轨、字幕轨，画面与时间轴都按这段切片裁好 |
| 达芬奇 OTIO | 达芬奇 / 任何吃 OTIO 的软件 | 一个 `.otio` 时间线（V1 轨上一条 Clip，媒体指向原片） |
| 降级包 | 什么软件都能进 | 一个文件夹：`片段.mp4` + `字幕.srt` + `文案.txt` + `导入说明.txt` |

两处默认行为值得知道：

- **默认不写你的剪映草稿箱**。草稿先落在本项目的 `export/jianying/` 下，你自己拷进去。
  想让它直接出现在剪映里，勾上「直接放进剪映草稿箱」——这个勾只在检测到剪映时才出现。
- **字幕样式不跟随**。草稿里的字幕是中性的白字（5 号、无描边），OTIO 只带时间轴，
  降级包里的 srt 不带样式。要定制外观，用「导出 → 硬字幕」把样式烧进画面。

界面上「交付」区跑完会给结果路径 + 「打开目录」，并逐条写清这次的特殊情况，例如
「降级包里放的是整段源视频（这段还没导出成片）」「已放进剪映草稿箱」。

剪映的草稿格式没有公开文档，本应用对齐的是剪映 5.9.0 的结构（`version=360000`）；
剪映大版本升级后如果打不开，先用降级包顶上，再把草稿发回来。

## 六、合并

把几个已导出的片段拼成一条。

1. 点左栏的片段，或点「添加本地文件」从磁盘选（可一次选多个；来自素材库的切片和本地文件都在同一张顺序表里）
2. 「预检」：列出每个来源的分辨率/帧率/编码/音轨等 8 个字段，**规格不一致会标红**
3. 选模式：
   - **快速拼接（copy）**：规格完全一致时用，秒出，不重编码
   - **精确合并**：规格不一致、或要统一到同一规格时用，重编码（scale+pad+fps+aresample；无音轨会自动补静音轨）
4. **输出目录**：默认是本项目素材目录下的 `merge/`，路径就显示在按钮上。想换地方点一下路径按钮，
   弹系统文件夹选择框；选完这个目录就一直用（本次会话内有效），点「清空」或重启应用会回到默认。
   换过一次之后预检不会再把路径改回默认——你选的目录说了算。
5. 「开始合并」。快速模式失败会自动转精确一次，并在结果里标 `fallback_used`。
6. 合并成功后，输出目录旁边那个「打开输出目录」按钮才会亮。点它直接在资源管理器里定位到成片所在的文件夹
   （不是打开成片本身——Windows 的「打开」对视频是播放，你要的多半是「找到文件在哪」）。
   按钮按**上一次成功的合并记录**开，所以重启应用后第一次进合并页它是灰的，跑完一次才亮。

**取消**有效（同样杀进程树）。

几个和输出目录有关的实际表现：

- 选出来的目录会先检查：必须是绝对路径、必须已经存在、不能是文件。目录不存在会被拒，
  先去资源管理器里建好再选——应用不替你猜路径。
- 目录只在你这次会话里记得。应用重启后回到默认目录，避免"上次随手选了个桌面，这次忘了"。
- 输出目录在项目素材目录之外时，只能通过「选择输出目录」按钮选一次；手打一个外部路径会被拒。
  这是为了防止别的功能借合并往任意路径写文件。

## 七、发布

从总结或切片生成草稿，三关自检后才让发。

1. 「新建草稿」（从总结）或切片台的「发布」→ 生成标题与正文（摘要字段已下线，不再生成、也不再发出去）
2. 三关实时给状态：

| 关 | 判什么 | 什么样叫 blocked |
|---|---|---|
| 内容确认 | 标题 ≤80、正文非空、**你勾了「我已阅读并确认」** | 标题超字 / 没勾确认 |
| 账号与视频 | 有 BV 号、有 aid（av 号，缺了发布时自动补）、草稿指向同一个视频、当前已登录 | 没登录 / 项目没有 BV 号（本地导入项目可在发布卡「视频号」里手填 BV 或 av 号） |
| 频率与重复 | 距上次发布 ≥60 秒（**按账号算**）、同一视频没有未撤回的笔记 | 太频繁 / 这个视频已经发过 |

3. 本地导入的视频没有 BV 号：在发布卡的「视频号」里填 BV 号或 av 号（任填一个），**保存草稿**后「账号与视频」才会放行。
4. 三关全绿 + 勾确认 → 「发布」。这是**全应用唯一不可撤销的动作**。
5. 发出去后：记录进「发布记录」（发过/撤过/失败分开计数）。「撤回」能让评论区里的笔记卡消失，本地记录保留为「已撤回」。

**失败**：`-509` 会重试（3 秒、6 秒），其它错误直接失败但**草稿正文不丢**。`12015`（验证码）不绕，去网页端手动处理。

**AI 披露**：`publish.disclose_ai` 开着时，正文末尾会自动带一行说明这是 AI 生成的内容。

## 九、任务、取消与恢复

- 顶栏「进行中 N」点开是任务面板：排队中/进行中/成功/失败/已取消，带进度、阶段、速度、ETA。
- **取消**：任何长任务（下载、转录、导出、合并、发布）都能取消。取消会杀整个子进程树，清 `tmp/{job_id}`，不留半成品。
- **重试**：失败任务点「重试」→ 生成一条**新记录**（`attempts+1`），旧记录留着。同一素材反复失败本身是信息。
- **重启恢复**：进程被强杀后再开，原来 running/queued 的任务会标成「上次退出时还没跑完（可以重试）」，项目阶段按磁盘上已有产物回推（不会出现「文件都在但说没下载」）。

**同一时刻的并发**：下载 2、转录 1、导出 2、合并 1、LLM 3。交互操作优先于批量。

## 十、出错时先看这几处

1. 状态栏有没有红字（依赖缺失 / 磁盘不足）
2. 顶栏任务面板那条任务的错误码与详情
3. 设置 → 关于 → 「打开日志目录」，看 `video-workbench.log` 尾部
4. 还是不明白：设置 → 关于 → 「导出诊断包」，里面有脱敏配置和最近日志
5. 命令行 `python -m video_workbench.desktop --check` 打一行 JSON，能确认依赖与库路径

错误码一览（前端会配中文文案）：

| 码 | 含义 | 谁的问题 |
|---|---|---|
| `VALIDATION` | 参数不合法 | 输入 |
| `NOT_FOUND` | 对象不存在 | 数据被删了/路径变了 |
| `CONFLICT` | 状态冲突（门禁没过、库被占） | 先处理状态 |
| `AUTH_REQUIRED` | 需要登录 | 去 bili-scribe 重登 |
| `DEPENDENCY_MISSING` | 缺 FFmpeg / 模型 / yt-dlp | 按提示装 |
| `PROCESS_FAILED` | 子进程失败 | 看详情里的原始输出 |
| `CANCELED` | 被取消 | 不用管 |
| `LLM_ERROR` / `LLM_AUTH` / `LLM_RATE_LIMIT` / `LLM_TIMEOUT` / `LLM_BAD_RESPONSE` | 模型侧 | 设置里测试连接 |
| `BILI_ERROR` / `RATE_LIMITED` / `GEO_BLOCKED` / `NETWORK` | 平台侧 | 网络类会重试，其它换源 |
| `DISK_FULL` | 空间不足 | 清盘 |
| `UNSUPPORTED` | 当前版本不支持 | 换条路 |
| `INTERNAL` | 兜底 | 导出诊断包 |
| `INTERRUPTED` | 上次退出时没跑完 | 重试 |

## 十一、命令行（批量与脚本化）

同一套能力，不开窗口也能用：`python -m video_workbench.cli <子命令>`。它只是 RPC 的另一层壳，
所以校验、错误码、数据库和窗口完全一致——不会出现"命令行能跑、界面不能跑"。

| 子命令 | 干什么 | 例子 |
|---|---|---|
| `info` | 版本、路径、依赖、体检状态 | `cli info` |
| `jobs` | 最近任务（默认 50 条） | `cli jobs` |
| `download` | 下载（可 `--backend bbdown`） | `cli download --url BV1xx411c7mD --quality 720P` |
| `transcribe` | 转录，给项目 id 列表 | `cli transcribe pj_abc` |
| `summarize` | 总结，可换角色 | `cli summarize pj_abc --role hardcore` |
| `clip` | 选段，可顺手导出 | `cli clip pj_abc --count 3 --export 1 --mode fast` |
| `merge` | 合并成片（`-o` 是输出文件名） | `cli merge a.mp4 b.mp4 -o 合并成片.mp4` |
| `run` | **一条命令跑完单稿闭环** | `cli run --project-id pj_abc --clips 2 --export 1 --mode fast` |

`run` 的顺序是：转录 → 总结 → 选段 → 导出。`--url` 时先下载再接着跑（`--skip-transcribe` /
`--skip-summary` 可跳过前两步，做局部重跑）。

**给脚本用**：加 `--json`，stdout 只有一行 JSON（进度和日志全去 stderr），可以直接
`| jq .` 或 `> result.json`。`--json` 放子命令前后都认（`cli --json info` = `cli info --json`）。

**退出码**（判断失败该不该重试就看这个）：

| 码 | 含义 | 该怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 任务跑了但失败（网络、模型、平台） | 看 `error.code`，可重试 |
| 2 | 参数或环境不对（项目不存在、门禁没过、没配模型） | 改配置/改参数，重试没用 |
| 3 | 被取消 | — |
| 130 | Ctrl+C | — |

`--timeout` 到点只是**不再等**（任务仍在后台跑），不会替你取消。

## 附：从零跑通一单（照着敲）

```bash
# 1. 自检：能不能装配起来
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe -m video_workbench.desktop --check

# 2. 开窗口
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe -m video_workbench.desktop
```

窗口里：

1. 新建任务 → 粘贴一个短 BV → 选 720P → 开始下载
2. 素材库 → 选中 → 开始转录（第一次会下模型）
3. 素材库 → 字幕 → 双击一行改个错字（停手就存）→ 导出 SRT
4. 素材库 → 总结 → 生成
5. 切片台 → 生成候选 → 选一条 → 导出（原比例）
6. 合并 → 添加两条切片 → 预检 → 快速拼接
7. 发布 → 从总结生成草稿 → 三关看一遍（不勾确认就不会发）

上面这条**完全用假 LLM 也能跑**（配好一个假的 `base_url` 即可，输出会被当成草稿）。想连真模型，在设置 → 模型里填地址和 key，点「测试连接」。

### 接入本机 magpie（局域网内的 OpenAI 兼容网关）

设置 → 模型 → 底部的 **「接入本机 magpie」**。点一下会建一张卡（地址 `http://127.0.0.1:3425/v1`、
密钥 `magpie`）并设为当前服务商，随后自动拉取模型清单填进卡里。

拉完记得点右下角 **保存**：卡片是「改了就标脏、点保存才落盘」的，不点保存只在本次会话里有效。

拉不到时按钮旁边会写原因。常见三种：

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| 连不上 | 网关没启动，或地址/端口不对 | 先确认那个服务在跑 |
| 鉴权失败（401） | 密钥不对 | 改卡里的 API Key |
| 被网关拒绝（403） | 被服务端前面的 CDN 按客户端特征拦了 | 填「上下文与长素材」里的代理，或改「请求 UA」 |

模型 id 里的斜杠（`auto/hy4-preview`、`Qwen/Qwen3-VL-Plus`）是**名字的一部分**，不是写错了。
只有当斜杠前的名字正好是一家服务商的 id（比如 `deepseek/deepseek-chat`）时，才会被当成「指名服务商」。

### 「模型只输出了思考过程，正文是空的」

推理型模型（magpie 的 `auto/*`、`deepseek-reasoner`）会先花预算思考，`max_tokens` 给小了正文就是空的。
报这个错时：把「上下文与长素材」里的 `max_tokens` 调大（默认 4096），或换一个非推理模型。
工作台不再把空正文当成功写进库里——以前症状是「总结生成成功，但内容是空的」。

### 生成总结时报「模型没有给出可用的总结 JSON」

模型把 JSON 写坏了（最常见：正文里带了裸换行）。现在程序会自己修一次，
修不好就**带着上一次的输出重问一次**，多数情况你会看到「已按更严格的要求重问一次」然后正常出稿。

两次都不行才报错，报错里会说明是截断还是格式：

- 后缀带「输出看起来被截断了」：把「设置 → 模型 → 上下文与长素材」里的**单次输出上限**调大（例如 4096 → 8192）。
- 没有截断提示：这家模型不太听话，换一个模型重出一版（总结页工具栏的「模型」下拉可以直接换，不必改默认设置）。
- 已经把预读跑完才失败的话，重跑会重新预读——先按上面两条调好再跑，别反复烧时间。
### 点了「测试连接」却报 Cloudflare / CDN 拦了

先在弹窗里确认报错的地址是不是你要测的那一家。两个已知坑：

1. **本机网关（`127.0.0.1`、`localhost`）**：程序对它一律直连，不看 `HTTP_PROXY`。如果你还是看到
   `405`/连不上，检查那个网关是否在跑（浏览器打开 `http://127.0.0.1:3425/v1/models` 试试）。
2. **公网网关报 `Error 1010: Access denied`**：这是网关前面的 Cloudflare 按「客户端指纹」拦的，密钥本身没问题。
   程序默认就用浏览器 UA（实测同一把 key、同一个地址：UA 写程序名一律 403，换浏览器 UA 就 200），
   所以还报 1010 只剩两条路：在「上下文与长素材 → 代理」填本机 Clash（`http://127.0.0.1:7897`），
   或换一个更新的浏览器 UA。改完都要重启程序才生效。
3. **`MissingSessionID` / 400**：这一家要求私有请求头。opencode 的 `x-opencode-session` 程序自动补；
   别家（Azure 的 `api-version`、自建网关的 `x-tenant` 之类）填在「上下文与长素材 → 额外请求头」。

如果指名了某一家却报「找不到服务商」：那张卡可能刚删掉还没保存，先保存再试——程序不会替你换一家去连。

### 这一版用哪个模型

总结页工具栏上、角色右边有一个下拉，列出你在「设置 → 模型」里配过的所有模型：

- 默认是 **跟随设置**（用「任务模型 → 总结」指定的那个）；
