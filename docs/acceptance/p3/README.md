# Phase 3 · 切片验收

切片台的验收分两段：**候选从哪来**（P3-01，纯逻辑，能自动跑）与**候选怎么变成
可导出的片段**（P3-02 起的校验/吸附/写库/界面，需要人看画面）。

本目录记录前者，并保留每次真机验收的证据。

## 二、P3-02 切点吸附与去重

### 为什么单独验

P3-01 的 5 条候选在 60 秒片子上必然互相重叠（每条 20 秒），所以两件事必须分开看：
**生成契约**（模型给什么）与**切点契约**（最终能剪出什么）。上面第 1–31 项关掉吸附，
只测生成；第 32–35 项开着默认值，测吸附与去重。

### 单测（`tests/wb/test_snap.py`，24 项）

```bash
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe -m pytest tests/wb/test_snap.py -q
```

| 组 | 覆盖 |
| --- | --- |
| 静音裁剪（4） | 起点落在句间空隙→后移到下一句开头；终点落在空隙→前移到上一句结尾；点在语音内部则不动；整段没语音时保留原值并写明「这一段里没有语音」 |
| 边界吸附（5） | 句边界命中标 `sentence`；超容差不挪且写原因；有词级时间戳时标 `word`；要词边界但没有词时间戳时**照实标 `sentence`**；吸附后零长度则回退原值 |
| 去重（5） | 同类重叠 ≥50% 丢低分；不相交都留；包含关系算重叠；跨类型（长段里套高光）都要留；重叠 11% 不算重复 |
| 整条流水线（6） | 原值保留；先剪静音再吸附；超长短段被截；越界被夹；无边界时 `boundary` 留空且写原因；吸附后才去重 |
| generate 接线（4） | 默认吸附；`snap=False` 只做区间夹取且不带 `boundary`；模型给的重叠候选去重；规则兜底候选也吸附 |

### 修掉的问题

1. **边界标签会撒谎**：`mode="word"` 时最初只要吸上了就标 `word`，但这段字幕没有词级
   时间戳时实际吸的是句边界——把"句级"记成"词级"，用户会以为切点精度到词。改成对比
   纯词边界集合（`_word_points`，没有词时间戳就是空表），命不中才标 `sentence`。
2. **`SNAP_TOLERANCE_MS` 定义在使用之后**：常量原本写在文件末尾的 P3-02 段，而
   `generate()` 的默认参数在模块加载时求值 → `NameError`。常量上移到文件头部常量区。
3. 验收脚本第 4 项原来断言"3–8 条"，但那是吸附前的数字；60 秒片 5 条 20 秒高光去重后
   只剩 2 条，这才是正确行为。脚本拆成两段（关吸附验生成、开吸附验去重）。

### 未验证

- 真语音边界处的实际观感（句尾常带 100–300ms 拖音，需要人看片子判断要不要再多剪一点）。
- 静音判定用的是"字幕段时间轴有没有覆盖"，不是真做静音检测——BGM 很大的片子字幕
  时间轴本身就不准，这里的偏差会传导到切片。
- 单句超过 90 秒（一口气讲完的长段）时，高光会被硬截到 90 秒，截断处可能落在句中；
  目前只记 note，不自动改到最近的句子结束。

### 修掉的问题

1. **热度按"条数"算会把长片段算赢**：原来 `heat_ratio = 段内弹幕数 / 最热桶条数`，
   20 秒里散着 4 桶 ×1 条 = 4，与 5 秒里 20 条比是 0.2——看着没问题，但 60 秒窗口
   能堆到 12 条，直接把一个十分钟里没人说话的段落算成全片最热。
   改成**密度**：本段每秒条数 ÷ 最热桶每秒条数。同时把区间改成左闭右开，
   相邻两段交界处不会被算两遍。
2. 验收脚本自己的三处错（不是代码错，记下来免得下次再犯）：
   - `$kinds` 在 prompt 模板里两种类型都写着，用"长文分段是否出现"判断模式 → 永远判成
     `segment`，于是 6 条候选全被 `kinds=("highlight",)` 校验掉，看起来像"模型没回"。
     改成读「想要的类型：」那一行。
   - 规则兜底在 59 秒片上只切 1 条（30 秒窗口），断言写"≥3"是假红。
   - `subtitle.get` 的 `kind` 是白名单，乱传只得 `VALIDATION`，拿不到 `NOT_FOUND`。

### 未验证

- 真模型挑出来的候选好不好看（这部分只能人工看片，等 P3-03 界面出来后做）。
- 超过 600 行字幕的抽样上限（`lines_text(limit=600)`）在 3 小时长片上会不会漏掉关键段落。
- 弹幕条数很大（10 万+）时 `heat_buckets` 的内存与耗时。

### 修掉的问题

1. **页面白屏（第一版）**：`clips.js` 最初用 `document.getElementById("page-clips")` 当容器，
   而路由契约是 `render(ctx) -> Node`。改成 `build()` 建持久节点 + `paint()` 重排骨架 +
   返回 `els.root`；`load()` 结尾调 `repaint()` 而不是 `render()`，避免把返回节点丢掉。
2. **磁吸按像素算会吸到十几秒外**：`SNAP_PX = 6` 在 600px 画布上对半小时片约等于 18 秒。
   新增 `SNAP_MS = 2000`（与 `clip.snap_tolerance_ms` 同口径），两个条件同时满足才吸。
3. **颜色字面量**：`timeline.js` 里 `pick("--acid-tx", "#000")` 的兜底色被 `check_colors` 拦。
   改成只回 token 值，空串就交给 canvas 默认，绘制前守卫。
4. **`timeline.state().dragging` 字段不存在**（实际是 `drag`）→ 播放时把自己的播放头拖回去。
5. **黑屏没解释**：`<video>` 读不到文件时只有一块纯黑。加了 `预览加载不了：…` /
   `这个项目还没有可播放的源文件。` 两种提示（截图里能看到）。
6. **`clip.analyze` 里 `job.to_dict()`**：`jobs.submit` 返回的是 dict，被 dispatch 包成
   `INTERNAL`。改成直接用。
7. **未配置模型时错误漏出任务**：`clipper.generate` 原来把裸调用写在 `except TypeError` 里，
   同级 `except Exception` 接不住 `ChatError(LLM_NOT_CONFIGURED)`。改成内层 try/except
   TypeError + 外层统一兜底；同时去掉真 `ChatClient.chat` 没有的 `note=` 形参。

### 未验证

- 真视频拖动的观感（jsdom 里只有事件与数值，没有真实 `<video>` 解码）。真机需要在桌面版点。
- 候选很多（>50 条）时左栏的滚动与首屏耗时，目前只测到 4 条卡片。
- 1100×720 最小窗口下的三栏挤压：截图都在 1360×860，窄窗只做过 CSS 层面的推断。

## 四、P3-04 切点编辑（帧对齐验收）

P3-04 的验收原文是"切点误差 ≤ 1 帧；锁定后重新生成不覆盖；手动切片可导出"。
前两项在 P3-03 已经半成品（锁定、±1 帧按钮），这一节补的是**帧从哪来**、
**对齐谁保证**、**手动切片凭什么算可导出**。

### 跑法

```bash
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe scripts/accept_p3_edit.py --config build/accept/p2.yaml
```

- 用真库真源文件（`short_60s.mp4`，25fps）——`frame_ms` 是 ffprobe 真读出来的，
  不是硬编码 40。
- 开跑先把该项目的候选全删（含 locked）：验收库是夹具，不从干净状态开跑会假红。

### 断言（21 项，全部通过）

| # | 断言 | 说明 |
| --- | --- | --- |
| 1 | `clip.candidates` 给出 `frame_ms` | 实测 40ms（25fps） |
| 2 | `fps` 与 `frame_ms` 自洽 | `1000/frame_ms` 与 `fps` 差 <3.5 |
| 3 | 帧长落在常见档位 | 25/30/29.97/60 或退回值 40 |
| 4 | 有源文件路径 | 没源文件只能按 25fps 估算 |
| 5 | 分析任务成功 | |
| 6 | 拿到候选 | |
| 7 | **对齐后误差 ≤ 半帧** | 实测最大 19ms（帧 40ms） |
| 8 | 对齐后全部落在帧栅格 | 逐条 `% frame_ms == 0` |
| 9 | 不指定 `align` 时原样保存 | 手动敲时间码不能偷偷改值 |
| 10 | `align` 传未知值被拦 | `VALIDATION`（只支持 `frame`） |
| 11 | 锁定后仍能微调切点 | 锁的是"重跑"，不是"手改" |
| 12 | 模型挂了任务仍成功 | 规则兜底 |
| 13 | 锁定的候选还在 | |
| 14 | 锁定候选切点没被重跑冲掉 | 锁前锁后同值 |
| 15 | 重跑确实换了别的候选 | 不是"啥都没做" |
| 16 | 重跑后除锁定项外都是规则兜底 | `notes.origin == "rule"` |
| 17 | 手动切片对齐后落在栅格 | 6013/26027 → 6000/26040 |
| 18 | 手动切片时长 ≥ 0.4 秒 | P3-05 导出直接吃这个 |
| 19 | 手动切片 `source=manual` | |
| 20 | 手动切片默认 `draft` | 要人确认才发（原则 7） |
| 21 | 对齐后不足 0.4 秒被拦 | 不能靠对齐把非法区间变成合法 |

### 界面这一侧

- 检查器末尾新增「一帧 40ms」——不写清帧长，用户不知道「±1帧」是 33ms 还是 40ms。
- 运输条新增「3 秒预卷」开关（默认开）：`player.playRange(start, end, {preRollMs})`
  提前 3 秒起播，让人听见切点前面那句话；**只影响预览起点，不动候选的 `start_ms`**。
- 拖动与 ±1 帧都走 `clip.update(align="frame")`，所以"误差 ≤ 1 帧"由后端保证，
  不靠界面凑巧；手动敲时间码（点「应用切点」）不传 `align`，写多少存多少。

### 修掉的问题

1. **`pick_project` 返回的是项目字典不是 id**：`candidate_clear(pid)` 把 dict 绑进 SQL，
   报 `sqlite3.ProgrammingError: type 'dict' is not supported`。两支验收脚本共用这个
   工具函数，取 `["id"]` 才对。
2. **`error_of` 返回的是 error 字典不是 code**：`error_of(...) == "VALIDATION"` 恒为假，
   三条"应该被拦"的断言全成了假红。改成 `.get("code")`。
3. **`start_stub()` 返回 `(server, base_url)`**，不是带 `base_url/stop()` 的对象；
   `stub.stop()` 反而把"验收通过"变成 AttributeError。
4. **验收库不清场会连环假红**：上一轮留下的 locked 候选让"锁定保护"的计数对不上，
   第二次跑还会多出一条 `('locked','llm')`。改成开跑前全删。

### 未验证

- 真机拖拽手感（jsdom 只有事件与数值，`<video>` 不解码）。截图里的黑屏是 mock 的
  源文件不在磁盘上，属于预期；真机要手动点一遍。
- 30/60fps 的真实片源（只在 25fps 的 60 秒片上验过；30fps 的 `frame_ms=33` 有单测覆盖）。
- 长片上拖动时时间轴重绘的帧率（60 秒片看不出瓶颈）。

## 五、P3-05 切片导出（真 ffmpeg 验收）

跑法：

```bash
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe scripts/accept_p3_export.py \
```

### 修掉的问题

1. **单条与批量各写一份提交逻辑会分叉**——抽出 `_clip_export_plan(...)`，两条路径
   共用同一份校验与字幕挑选（否则「批量那条漏了竖屏校验」这种 bug 必然出现）。
2. **`job.retry` 是新建任务**——界面拿到新 id 才能继续轮询；直接复用旧 id 永远读到
   `failed`，重试按钮看着点了没反应。
3. **`clip.exports` 不带 `batch_id`**——队列分不出哪几条是一批的，只能靠时间猜。
   任务 payload 里本来就有，取出来即可。
4. **勾选会顺带选中那条切片**——复选框在卡片内，点击冒泡到卡片。`stopPropagation`。
