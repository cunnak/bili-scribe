# 切片候选抽取（P3-01）

你在替一档中文视频挑切片。读者会在手机上刷到这些片段，**没有前情提要**——
所以一个候选能不能立住，只看它自己这几十秒里有没有把一件事讲完整。

## 输入

- 视频总时长：$duration
- 想要的类型：$kinds
- 候选数量：不超过 $count 个
- 字幕（形如 `[起始-结束] 文本`，单位毫米秒，已带标点）：
$lines
- 弹幕热度：$danmaku

## 两种类型

- `highlight`（高光短切片）：**15–90 秒**。一个观点/一次反转/一个漂亮的反问。
  适合当短视频单独发出去。
- `segment`（长文分段）：**120–480 秒**。一整段论证、一个完整章节。
  适合把长视频拆成有序的章节。

## 挑什么

1. **自足**：开头就能听懂，结尾有落点。别从半句话开始，别在句子中间停。
2. **有信息增量**：给出判断、反例、步骤、数字，而不是寒暄和"我们下期见"。
3. **弹幕热的地方优先**，但**热度不等于内容好**——观众也可能只是在刷梗。
4. 同一个位置不要给两个高度重合的候选。

## 输出

只输出 JSON，不要解释、不要代码块围栏：

```json
{
  "candidates": [
    {
      "kind": "highlight",
      "start_hint_ms": 125000,
      "end_hint_ms": 168000,
      "title": "为什么他坚持不做低价",
      "reason": "观点完整，有反问和结论",
      "quote": "你卖得便宜，不是因为成本低，是因为你不敢定价。",
      "score": 87,
      "tags": ["观点", "定价"]
    }
  ]
}
```

字段要求：

- `kind`：只能是 `highlight` 或 `segment`，必须是本次要求的类型之一。
- `start_hint_ms` / `end_hint_ms`：整数，毫秒。**从上面字幕的时间码换算**，不要凭空编。
- `title`：不超过 18 字，具体，别用"精彩片段"这类空话。
- `reason`：一句话说清为什么这段能独立成立。
- `quote`：这段里最有代表性的一句原话，**逐字抄字幕**，不要改写。
- `score`：0–100 的整数，你对"这段值得被剪出来"的判断。
- `tags`：1–3 个短标签。

宁可少给，也不要凑数：给不出 3 个够格的，就给 2 个。
