# bili-scribe

给一个 B站 视频，把它的内容读一遍，写成总结，发到那个视频的评论区。手动选视频、登录、自动评论，这条链是闭合的。

一个本地运行的、个人学习研究用途的技术演示项目。

> **[请先读 DISCLAIMER.md](DISCLAIMER.md)。** 本项目与哔哩哔哩官方无关、未获授权；使用的接口不是官方公开能力；自动化操作账号**可能违反平台用户协议并导致账号受限**，风险由使用者自行承担。不支持批量、刷屏、验证码绕过等用法。

## 先看这段：合规与风险

这比功能重要，别跳。

**接口不是官方的。** B站 开放平台（open.bilibili.com）对个人开发者开放的是视频稿件管理、创作者数据、直播互动、消息推送，**没有发表评论的接口**，也没有视频字幕的出口。所以这个工具走的是 Web 端接口。

**参考文档的母库已经关停。** 2026 年 1 月 28 日，长期作为社区接口依据的 `SocialSisterYi/bilibili-API-collect` 收到 B站 委托律所的律师函后永久下线并删除文档，指控理由是"对哔哩哔哩平台非公开的 API 接口及其调用逻辑、参数结构、访问控制及安全认证机制进行系统性收集、整理，并以技术文档、代码示例等形式向不特定公众传播"。这个项目把接口路径当作本地自用实现细节，不打包分发、不写成教程。

**自动发评论可能违反用户协议，也有封号风险。** 只用在自己的账号上。

**这个工具刻意不做的事：**

- 不绕过评论验证码。碰到 `12015` 就停下来，让人去网页端手动处理。
- 不做多账号轮换、不做批量评论列表、不做定时刷评。
- 不共享凭据、不上传凭据、不把接口包装成对外服务。
- 不在评论区塞外链或话题标签——那些是典型的垃圾评论特征。

**默认有人工确认。** 总结生成后停在预览页，你过目、可以改、勾选确认，评论才会发出去。想全自动可以关掉，但别关。

## 快速开始

```bash
cd bili-scribe
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

copy config.example.yaml config.yaml   # 然后把 llm.api_key 填上
python run.py
```

浏览器会自动打开 `http://127.0.0.1:8818/`。想先确认环境有没有问题：

```bash
python run.py --check
```

它会检查 api_key、数据目录可写性、二维码库、加密库和应用导入，把"跑起来才发现"的问题提前暴露出来。

### 操作顺序

1. **登录**：点「获取登录二维码」，用 B站 App 扫码确认。成功后凭据加密存到本机。扫码走不通时，展开「手动填 Cookie」贴 `SESSDATA` 和 `bili_jct`。
2. **选视频**：粘贴链接、`b23.tv` 短链、BV 号或 av 号。带 `?p=3` 就总结第 3 P。
3. **等总结**：进度面板会逐条列出每个素材源拿到了什么、为什么没拿到。
4. **确认**：右侧看预览，评论正文可以直接编辑，字数实时校验。勾选确认后发布。
5. **可撤回**：发完的记录在左下角，随时能撤回，撤回后能重新发。

## 用快捷方式打开（Windows）

双击 `scripts\create-shortcuts.bat`，桌面会出现两个快捷方式：

| 快捷方式 | 行为 |
|---|---|
| `bili-scribe` | 静默启动，不弹控制台窗口。适合日常用 |
| `bili-scribe-debug` | 带控制台启动，能看到日志。出问题时用这个 |

也可以直接双击 `start.bat`。它把三件事串在一起了：

1. 没有 `.venv` 就自动创建虚拟环境（需要已安装 Python 3.10+）
2. 自动安装依赖
3. 启动服务并打开浏览器

**首次运行会慢**：要建环境装依赖，大概一两分钟，而且这一步需要联网。首次启动时那个快捷方式会**故意保留控制台窗口**，就是为了让你看得见进度——装依赖失败的样子和不启动是一样的，不给可见反馈会让人以为程序坏了。依赖装好之后，第二次起就恢复静默。

如果桌面快捷方式不生成，直接双击 `start.bat` 效果一样，只是会留一个控制台窗口。

## 分享给别人

把整个 `bili-scribe` 目录打包发过去就行。对方那边需要：

1. **自己装 Python 3.10+**（安装时记得勾 "Add python.exe to PATH"）
2. 解压后双击 `start.bat`
3. 在界面里**用自己的 B站 账号扫码登录**，在 `config.yaml` 里**填自己的大模型 api_key**

三条都不可省略，也没有办法替对方省掉——每个人用各自的账号和各自的模型额度，本项目不涉及任何凭据共享。

打包时应当排除：`.venv/`、`__pycache__/`、`config.yaml`、`*.db`、`key.bin`。这些要么是机器相关的，要么含你自己的登录凭据。

想自己打一个干净的发布包：

```bash
python scripts/package.py
```

会在 `dist/` 下生成一个 zip，已经排除了上面这些内容。

## 出问题先看这里

### 按钮点了没反应，二维码出不来

九成是下面两种之一。

**一、页面没有被后端托管。** 双击 `index.html` 打开，或者从某个预览面板里打开，它就是一个静态文件——所有按钮都不工作，因为 `/api/...` 根本不存在。现在页面会自己在顶部弹一条红色横幅把这件事说清楚，并把按钮置灰。

正确打开方式是从 `http://127.0.0.1:8818/` 进。`python run.py` 会自动帮你打开浏览器。

**二、缺 `qrcode` 或 `Pillow`。** 这两个只是扫码通道的依赖，缺了应用照样能启动、手动填 Cookie 也照样能用，所以特别容易被忽略。此时界面会把扫码按钮置灰、给出安装命令，并自动展开 Cookie 兜底面板。

```bash
pip install "qrcode[pil]"
```

### 一次性自检

```bash
python run.py --check
```

逐项报告 api_key、数据目录写权限、qrcode、cryptography、应用导入。有一项不过就以退出码 1 结束。

### 其他常见报错

| 现象 | 通常是 |
|---|---|
| `-352`、字幕恒为空 | 登录态失效，重新扫码 |
| `-101` nav 未识别到登录态 | Cookie 过期，或手工填时漏了 `bili_jct` |
| `12015` 需要验证码 | 去网页端手动发一条评论解除。本工具不绕过验证码 |
| `12051` 重复评论 | 本地记录被清但评论还在，先去评论区删掉那条 |
| 总结一直是"素材未覆盖" | 该视频既无字幕也无弹幕，只剩标题简介 |

## 它是怎么工作的

### 五个阶段

```
输入解析 → 内容采集 → 大模型总结 → 人工预览确认 → 发表评论
```

最后一格会写回本地去重表，所以同一个视频再次请求时，第一步就被拦住了。

### 素材降级链

排序依据是"离视频内容本体有多远"：

| 顺位 | 来源 | 可信度 | 说明 |
|---|---|---|---|
| 1 | 人工字幕 | 高 | UP 主上传或平台校对，最贴近原意 |
| 2 | B站 AI 字幕 | 中 | 语音识别，有同音字和断句错误 |
| 3 | 弹幕 | 低 | 只反映观众反应，**不等于视频讲了什么** |
| 4 | 标题／简介／标签 | 低 | 撑不起内容级总结 |

**字幕必须登录才有。** `x/player/wbi/v2` 对匿名请求恒定返回空字幕数组，没有免登录路径——这是实测结论，不是猜测。弹幕反过来，免登录可拿。

这条链全走空时，采集器直接报错退出。不拼凑。一份基于标题和简介编出来的总结看着像模像样，实际上是把模型的先验知识伪装成了视频内容，那比报错糟糕得多。

### 长素材怎么处理

素材超过 `max_input_chars` 就分段预读，每段先出结构化笔记，再拿笔记做归约。分块数有上限（8 段），避免一个长视频把成本炸开。

### 防止模型编内容

提示词里下了几条硬约束：只用素材里的信息；弹幕必须标明是观众视角；素材不足就写"素材未覆盖"；不评价 UP 主。时间戳只在素材真实出现过时才允许填进 `timeline`，素材没有时间戳就返回空数组。

另外，字幕是按 15 秒时间窗聚合后才给模型的。平台 AI 字幕既没标点又被切得极碎，原样拼进去，模型判不出章节边界，也容易被支离破碎的语序带偏。

## 三道发布闸门

评论是这个应用里唯一不可撤销的动作，所以约束最多。

**人工确认。** `require_confirm` 为真时，没有显式确认一律不发。

**本地去重。** 发请求之前先查本地记录。B站 对相同内容重复发送返回 `12051`，与其等平台拒绝，不如自己先拦住。同一视频只允许有一条未撤回的评论。

**频率限制。** 两次发布之间强制间隔，默认 60 秒，避免踩到 `-509` 限流。

### 评论错误码速查

| 码 | 含义 | 本工具的处置 |
|---|---|---|
| `-509` | 请求过于频繁 | 退避重试最多 2 次 |
| `-111` | csrf 校验失败 | 提示重新登录 |
| `12015` | 需要评论验证码 | **硬停**，请去网页端手动处理 |
| `12016` | 内容含敏感信息 | 硬停，提示改措辞 |
| `12025` | 评论字数超限 | 组装阶段已按 `max_comment_chars` 裁剪 |
| `12035` | 被 UP 主拉黑 | 硬停 |
| `12051` | 重复评论 | 本地去重应已前置拦截 |
| `12002` / `12052` | 评论区已关闭 | 硬停 |
| `-102` | 账号封停 | 硬停 |

## 配置

改 `config.yaml`。几个值得注意的：

```yaml
llm:
  base_url: https://api.deepseek.com/v1
  model: deepseek-chat
  max_input_chars: 24000    # 超过就分块归约

collect:
  danmaku:
    also_with_subtitle: false   # 有字幕时是否也抓弹幕，开了会明显增加 token 消耗

publish:
  require_confirm: true       # 别改
  min_interval_seconds: 60
  disclose_ai: true           # 在评论里注明 AI 生成
```

`base_url` 只要兼容 OpenAI 的 `/chat/completions` 就能用，不绑定厂商。

```
├── bili_scribe/

│   ├── infra/                 基础设施：直接跟外部系统打交道
│   │   ├── endpoints.py       接口常量与错误码表
│   │   ├── wbi.py             WBI 签名

│   │   ├── llm.py             OpenAI 兼容适配器
│   │   └── store.py           SQLite：凭据、任务、发布、去重
│   ├── core/                  领域层：业务规则，不碰 HTTP
│   │   ├── resolver.py        输入 → 稿件 + 分P
│   │   ├── collector.py       降级链采集
│   │   ├── summarizer.py      提示词编排与结构化输出
│   │   ├── composer.py        评论组装与裁剪
│   │   └── publisher.py       发布、去重、频控、撤回
│   └── app/
│       ├── main.py            FastAPI 接口
│       └── static/index.html  单页前端（零构建）
├── tests/
│   ├── smoke_test.py          后端冒烟：离线单元检查 + 真实 HTTP 探测
│   └── frontend_test.js       前端回归：DOM 桩真实执行页面脚本
└── 数据默认落在 ~/.bili-scribe/
```

三层之间是单向依赖：`app → core → infra`。领域层不直接发 HTTP，所以换掉传输方式不影响业务规则。

`smoke_test.py` 会真的去请求一次 B站 的扫码接口（匿名取码，不涉及登录）。前端的 29 项里，A 组专门盯着"页面没连上后端"这个曾经出过事故的场景。

## 凭据怎么存

`~/.bili-scribe/bili-scribe.db` 里存登录凭据，用 Fernet 对称加密，密钥单独放在 `key.bin`。这挡不住能读你整个用户目录的人，但能保证数据库文件被单独拷走时凭据不可读。

没装 `cryptography` 时会退回明文并打印警告——功能优先，但风险要说不出来。

服务只监听 `127.0.0.1`。**别改成 `0.0.0.0`**，这个进程持有你的登录凭据。

## 已知限制

**字幕路径依赖登录态。** 未登录时字幕恒为空，会直接掉到弹幕或元数据档。所以不登录能用，但总结质量会明显下降。

**接口没有稳定性承诺。** 这些路径随时可能变。所有调用点都在检查 JSON 里的 `code` 而不是 HTTP 状态码——B站 大量接口在 200 的情况下返回失败，只看状态码一定会漏判。

**平台侧 AI 摘要只做对照。** `conclusion/get` 能拿到平台自己生成的摘要和分段提纲，界面上显示出来供你比对，但它不参与本次生成，也不会冒充成这个工具的输出。

**没有做自建 ASR。** 无字幕时下载音轨自己转写这条路是通的，而且能彻底绕开字幕权限，但需要额外的模型额度，当前版本没接。这是下一步的扩展点。

**硬字幕 OCR 也没做。** 视频画面里内嵌字幕的情况，需要抽帧加 OCR，同样留作扩展。
